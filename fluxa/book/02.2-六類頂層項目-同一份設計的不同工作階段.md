# 2.2 六類頂層項目：同一份設計的不同工作階段

Fluxa 的頂層項目可以分成六類。把它們放在同一張表裡，最容易看出「函式回傳一個值」與「程序傳送一串 token」的差別：

| 項目 | 形式 | 執行時間 | 適合表達 |
| --- | --- | --- | --- |
| `const` | `const NAME: T = expr;` | 編譯期 | 係數、通道深度、陣列大小、硬體常數 |
| `fn` | `fn NAME(...) -> T { ... }` | 函式被呼叫時 | 一般、具型別的值級計算 |
| `comb fn` | `comb fn NAME(...) -> T { ... }` | 合成時展開 | 零週期的組合邏輯 |
| `comptime fn` | `comptime fn NAME(...) -> T { ... }` | 編譯期 | 根據編譯期參數計算常數或形狀 |
| `task` | `task NAME(...) { ... }` | 程序執行期 | 可與其他程序透過通道連接的元件 |
| `test` | `test NAME { ... }` | 測試執行期 | 建立環境並驗證可觀察行為 |

### `const`：把「固定」寫進語意

```fluxa
const DEPTH: u32 = 4;
const COEF: [i8; 4] = [1, 2, 3, 4];
```

第一個常數決定通道或陣列的形狀；第二個常數是硬體常數陣列。`const` 的值必須在載入程式時就能求出，不能依賴執行期才出現的 channel token。

這裡的「編譯期」不表示編譯器會把每個常數最佳化得更快，而是表示**設計形狀已固定**。例如：

```fluxa
task Pair(x: in chan<u8>, y: out chan<(u8, u8)>) {
    for v in x {
        y.send((v, v));
    }
}
```

通道元素是 tuple 時，型別檢查會分別檢查每個位置。通道不會把 `(3, 300)` 偷偷變成 `(3, 44)`；錯誤會在送出的落點被攔下。

### `fn`：一般值級函式

```fluxa
fn add_one(x: u8) -> u9 {
    x + 1
}
```

`fn` 有具名參數與可宣告的回傳型別。它表達「給我一個值，我算出一個值」。這很適合封裝純計算，例如解碼指令、算位元切片、產生布林判斷。

`fn` 並不表示「永遠只在軟體模擬執行」。當它被 `task` 呼叫時，工具可以把它內嵌到資料路徑，或合成為組合模組。第七章會說明實際降階方式。

### `comb fn`：明確要求零週期

```fluxa
comb fn is_negative(x: i8) -> bool {
    x < 0
}
```

`comb fn` 是 `fn` 的硬體語意更明確的版本：合成時應展開成組合邏輯，而不是形成有狀態的循序控制。它適合解碼器、位元操作、布林選擇與資料路徑中的小算式。

`comb fn` 仍必須遵守型別安全。比較結果是 `bool`，不能把 `bool` 當成任意寬度的整數使用；`bit` 與 `bool` 的語意也不同，第三章會說明。

要記住一條限制：目前 Fluxa v1.0 **不會檢查組合路徑是否超過目標 FPGA 的時脈週期**。所以 `comb fn` 表達的是意圖，不是「這條路徑在任何裝置上一定跑得過」。

### `comptime fn`：宣告編譯期計算的意圖

```fluxa
comptime fn clamp_limit(n: u8) -> u8 {
    if n > 16 {
        16
    } else {
        n
    }
}

const LIMIT: u8 = clamp_limit(8);
```

`comptime fn` 在語意上用來做編譯期計算：輸入必須是編譯期已知的值，輸出必須是封閉值。它適合計算查表大小、位元寬、位元組數，或依固定參數產生常數與程式形狀。

在目前的 v1.0 實作中，模擬器能解析 `comptime fn`，而把它的呼叫放在 `const` 初始值裡，就會在程式載入、求解常數時得到結果。不過，實作尚未提供一套獨立且嚴格受限制的編譯期函式求值器，也不會阻止你在普通 task 中呼叫它。因此，這個關鍵字應理解為**設計意圖**；真正需要由硬體工具可靠處理的可變形狀，仍應優先使用 const generic。第 3 章會說明如何把寬度與長度參數化。

### `task`：把計算放進程序網路

```fluxa
task Copy(x: in chan<u8>, y: out chan<u8>) {
    for v in x {
        y.send(v);
    }
}
```

`task` 不只是函式換了一個關鍵字。它可以有通道參數，也可以在 body 裡執行 `spawn`、`recv`、`send`。當 `spawn Copy(...)` 執行時，傳入的通道端點所有權會轉移到新程序。這個 task 因而能成為更大網路中的一個節點。

`task` 也能回傳值：

```fluxa
task Sum(x: in chan<u8>) -> u16 {
    let mut total: u16 = 0;
    for v in x {
        total += v;
    }
    total
}
```

不過在資料流元件中，通常以輸出通道表達結果，而不是讓呼叫端等待 task 的回傳值。原因是：回傳值把消費者綁在程序呼叫上；通道則保留元件可組合、可背壓、可並行的能力。

### `test`：驗證契約，而不是貼上一個 happy path

```fluxa
test copy_preserves_order {
    let (tx, rx) = chan::<u8>(depth = 4);
    let (ty, ry) = chan::<u8>(depth = 4);
    spawn Copy(rx, ty);
    for v in [1, 2, 3] {
        tx.send(v);
    }
    tx.close();

    let mut got = [];
    for v in ry {
        got = concat(got, [v]);
    }
    assert got == [1, 2, 3];
}
```

測試不只是「呼叫函式」。它還建立真實的有界通道、啟動 task、送出 token、關閉送端，最後按順序接收並斷言。

這也是本章最後要完成的元件：`SaturatingDouble`。本章會先寫一個容易誤判的版本，再用型別與明確轉換把它修好。
