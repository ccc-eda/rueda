# 3.6 窄化必須明確：四種轉換各有不同契約

當來源值域放不進目標型別時，程式不能保持沉默。你必須說明資訊將如何遺失。

### `as`：明確轉換，但不替你選策略

```fluxa
let x = value as u16;
```

`as` 讓整數型別之間的轉換明確化，且不像 `.to` 那樣接受 `round` 與 `ovf` 參數。它適合表達型別明確、結果可安全表示的轉換；若來源可能超出目標範圍，就應改用 `.wrap::<T>()`、`.sat::<T>()` 或 `.to::<T>()`，把截位與飽和意圖直接寫進程式。

Fluxa v1.0 的行為模擬器會診斷超出目標值域的 `as`；硬體後端則以目標寬度形成轉換電路。因此，需要跨行為模擬、編譯模擬與硬體後端維持單一契約時，不應把 `as` 的超範圍行為當成可攜策略，而應使用帶明確 `ovf` 的方法。

若你的意圖是「重新解讀二補數位元」，應使用明確的回繞轉換，而不是把 `as` 當成任意位元 reinterpretation。

### `.wrap::<T>()`：保留目標需要的低位元

```fluxa
let x = 300.wrap::<u8>();      // 44
let y = (-1).wrap::<u8>();     // 255
let z = 255.wrap::<i8>();      // -1
```

`.wrap::<T>()` 取低  $N$  位元，再依目標整數型別的兩補數語意解讀。這正適合：

- 計數器模  $2^N$  遞增。
- CRC、雜湊或位元串演算法中明確要求的模運算。
- 協議規定低 N 位元有效的欄位。

如果規格沒有要求模運算，回繞通常比飽和更危險，因為它可能把嚴重超出的值變成一個看似正常的小值。

### `.sat::<T>()`：夾在目標上下界之間

```fluxa
let x = 300.sat::<u8>();       // 255
let y = (-1).sat::<u8>();      // 0
let z = 255.sat::<i8>();       // 127
```

飽和適合影像、感測器與音訊處理：超出物理範圍時，寧可停在最大值或最小值，也不要把意義不明的小值送到下一級。

### `.to::<T>()`：可同時指定捨入與溢出策略

```fluxa
let x = value.to::<u8>(round = nearest, ovf = sat);
```

`.to` 是用途最廣的明確轉換。它能指定：

- `round = trunc | nearest | even`
- `ovf = wrap | sat | check`

轉換到整數時，若來源含有多餘的小數位，仍要用 `round` 決定如何捨去；若來源本來就是整數，捨入選項才沒有作用。轉換到定點數時，捨入與溢出策略都很重要。下一節會完整說明定點數。

### 明確回繞運算子 `+%`、`-%`、`*%`

Fluxa 也提供：

```fluxa
let mut counter: u8 = 255;
counter = counter +% 1;        // 0
```

`+%`、`-%`、`*%` 的結果型別等於左運算元的型別，並在該寬度回繞。v1.0 要求左運算元必須是具有已宣告型別的變數：

```fluxa
let next = (counter + 1).wrap::<u8>();   // 任意運算式都可以
counter = counter +% 1;                  // 左側必須是型別化變數
```

這個限制迫使「哪裡發生回繞」清楚可見，也讓模擬器與合成器能用同一條規則判斷。

### 一個完整對照：`clamp_add`

```fluxa
fn clamp_add(a: u8, b: u8) -> u8 {
    let s = a + b;       // 先得到完整值域 0..=510
    s.sat::<u8>()        // 再明確飽和到 0..=255
}
```

相較之下：

```fluxa
fn broken_add(a: u8, b: u8) -> u8 {
    a + b                // E0301：來源不能完整落點到 u8
}
```

兩者的差別不在語法，而在資訊遺失時的契約。`clamp_add` 明確承諾「最大 255、最小 0」；`broken_add` 沒有承諾任何超範圍行為，所以工具必須拒絕它。

### `wrap`、`sat`、`check` 進入硬體後的差別

| 策略 | 行為模擬 | 合成硬體 |
|---|---|---|
| `wrap` | 取低位元 | 硬體自然按位寬回繞 |
| `sat` | 夾至上下界 | 需要比較器與多工器 |
| `check` | 超範圍即令模擬失敗 | 不產生額外保護邏輯，也不會自動送出錯誤旗標 |

`check` 是「在模擬中驗證契約」，不是硬體的保護機制。若規格要求晶片即使收到異常值也必須保持可預測行為，應使用 `wrap` 或 `sat`；若使用 `check`，就必須另外設計錯誤旗標或握手協定，不能假設硬體會「拋出例外」。
