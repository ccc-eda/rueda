# 9.9 練習與交付摘要

## 9.9.1 合成 4 階 FIR

完成以下流程並記錄每一步的輸出：

```sh
cargo build --release -p rueda
reda check fluxa/examples/fir4.fx
reda synth --top Fir fluxa/examples/fir4.fx
reda fpga --top Fir --pcf icebreaker.pcf --bin fir4.bin fluxa/examples/fir4.fx
```

回答：

- 網表中有幾個 task 實例？幾條 FIFO？
- 乘法器數量與你的排程設計一致嗎？
- FIFO 閘數占比是多少？是否觸發警告？
- 時序最差路徑落在哪一類邏輯？

## 9.9.2 完成一次 FPGA 位元流

依你的開發板補上正確的 `pcf` 或 `lpf`，完成一次可燒錄的位元流。至少記錄：

- 裝置型號與封裝；
- 時脈頻率；
- 所有串流埠的接腳；
- 工具版本與命令；
- 燒錄與觀察結果。

若沒有實體板子，至少完成佈局繞線與時序報告，並說明缺少哪一段驗證。

## 9.9.3 選做：ASIC 流程

使用內建 `vlib` 或 `sky130` 完成一次 ASIC 流程：

```sh
reda asic --pdk sky130 --verilog fir.v --def fir.def --gds fir.gds --top Fir fir.fx
```

比較 FPGA 與 ASIC 的面積與時序定義差異。注意：兩者的「面積」不是同一種單位，不能直接比較數字大小。

## 9.9.4 章末交付摘要

寫一份設計交付摘要，至少包含：

| 欄位 | 內容 |
| --- | --- |
| 頂層 task | 名稱與參數 |
| 介面 | 每個通道的 data/valid/ready/close |
| 時脈與重置 | 頻率、極性、接腳 |
| 資源 | LUT、FF、BRAM、DSP |
| 頻率 | 目標與實際時序結果 |
| 產物 | 位元流／GDS／DEF 路徑 |
| 重現命令 | 從原始碼到產物的完整命令 |
| 已知限制 | 尚未驗證的假設與未實作功能 |

## 9.9.5 下一章

現在你已經有了一份實際的網表與產物。下一章要回答更關鍵的問題：**我們怎麼知道這個網表中的行為，和原本的行為模型完全一致？**

這需要三層證據：行為直譯器、編譯後模擬器與閘級模擬器。它們不是三種「跑起來很像」的工具，而是同一份語意在不同層級上的投影。第 10 章會建立這套跨層等價驗證。
