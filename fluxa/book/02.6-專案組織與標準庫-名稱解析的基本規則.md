# 2.6 專案組織與標準庫：名稱解析的基本規則

### 多個 `.fx` 檔合併成同一程式

Fluxa 可以像編譯 Verilog 多檔案一樣合併程式：

```sh
reda sim codec.fx datapath.fx tests.fx
```

合併後，所有使用者定義共用一個全域命名空間。因此 `codec.fx` 與 `datapath.fx` 都不能各自宣告同名的 `Fir` task、`twice` 函式或 `DEPTH` 常數；重複名稱是載入錯誤。

`--test` 與 `reda list` 看到的是合併後的全部測試：

```sh
reda list codec.fx datapath.fx tests.fx
reda sim codec.fx datapath.fx tests.fx --test fir_vectors
```

這個模型簡單而可預測。大型專案若需要模組化，可以靠檔案責任與嚴格命名維持秩序；Fluxa v1.0 的 `use`／`type` 宣告目前只會被解析後略過，不建立匯入別名或型別別名。

### 標準庫何時載入？

只有當任一來源檔含有 `std::` 時，載入器才把 Fluxa 標準庫併入程式。命名規則如下：

1. 使用者自己的同名定義優先。
2. `std::Name` 與 `Name` 指向同一實際名稱。
3. 多段名稱以最後一段作為實際名稱，例如 `std::dsp::Name` 實際就是 `Name`。
4. 標準庫元件不是黑盒 IP；它們本身就是 Fluxa task 網路，可以被模擬、檢查與合成。

例如：

```fluxa
task Mm4(a: in chan<i8>, b: in chan<i8>, c: out chan<i32>) {
    spawn std::SystolicMatmul::<4, 8, 32>(a, b, c);
}
```

`std::SystolicMatmul` 是參數化的脈動矩陣乘法產生器。參數依序是矩陣維度 `N`、輸入位寬 `AW` 與累加位寬 `CW`。

### 一個容易誤會的名稱解析規則

因為 `std::Name` 與 `Name` 是同一項目，使用者若定義：

```fluxa
task SystolicMatmul(/* ... */) { /* 使用者版本 */ }
```

會覆蓋標準庫同名項目。這是刻意的「使用者優先」規則，但大型專案應避免無意碰撞，否則很難追查某個 `spawn` 到底展開成哪一版。
