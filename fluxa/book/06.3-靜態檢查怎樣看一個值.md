# 6.3 靜態檢查怎樣看一個值

### 6.3.1 抽象值：一個值可能落在哪裡

Fluxa 的靜態分析把程式中的整數值抽象成一個封閉區間：



$$
[lo, hi]
$$



這個區間不必剛好等於型別的全部合法值域，而應涵蓋目前控制流程中可能出現的值。例如：

```fluxa
fn f(x: u8) -> u16 {
    let y = x + 1;
    y
}
```

分析過程是：

1. `x` 的參數型別是 `u8`，所以初始值域是 `0..=255`。
2. 常數 `1` 的值域是單點 `1..=1`。
3. 加法採端點規則，因此 `x + 1` 的值域是 `1..=256`。
4. `u16` 的值域是 `0..=65535`，完整包含 `1..=256`，所以可以無損落點。
5. 回傳型別同樣檢查通過。

若把回傳型別改成 `u8`，分析就會得到：

```text
the value's range 1..=256 does not fit u8 (range 0..=255)
```

這比只說「回傳值可能溢出」更有用：它直接列出來源範圍與目標範圍。

### 6.3.2 運算式如何推進值域

整數區間分析沿用第 3 章的端點規則：

| 運算 | 推導方式 | 範例 |
| --- | --- | --- |
| `+` | 下界相加、上界相加 | `u8 + u8 → 0..=510` |
| `-` | 最小下界減最大上界、最大上界減最小下界 | `i8 - i8 → -255..=255` |
| `*` | 檢查四個端點組合 | `i8 * i8 → -16256..=16384` |
| `>>` | 依移位量縮小正負範圍 | `i16 >> 1 → -16384..=16383` |
| `/`、`%` | 排除零後以商與餘數端點推導 | `u8 / u8 → 0..=255` |
| 明確回繞運算 | 回到目標型別範圍 | `+%`、`-%`、`*%` |

值域不只是一個「最大值」。它必須同時保留最小值，因為有號整數的硬體成本往往由負端與正端共同決定。

分析也會追蹤布林值與部分常數：

```fluxa
let flag = x > 100;
```

`flag` 是 `bool`，不能再當成 `0` 或 `1` 的整數使用。若後續需要計數，必須明確轉換，並承擔窄化或溢出策略。

### 6.3.3 落點：值域真正受到約束的地方

單純知道運算式的值域還不夠。Fluxa 會在值「落進某個型別」時檢查完整性。常見落點包括：

| 落點 | 範例 |
| --- | --- |
| 型別化 `let` | `let x: u8 = expr;` |
| 賦值 | `x = expr;` |
| 複合賦值 | `x += expr;` |
| 通道傳送 | `tx.send(expr);` |
| 函式或 task 引數 | `f(expr);` |
| 回傳值 | `return expr;` |
| 陣列元素 | `a[i] = expr;` |

判斷原則是：



$$
source \subseteq target
$$



若來源區間完整包含於目標區間，轉換無損；若不是，就必須由設計者明確選擇飽和、回繞或檢查失敗。
