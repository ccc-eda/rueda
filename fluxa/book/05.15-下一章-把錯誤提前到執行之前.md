# 5.15 下一章：把錯誤提前到執行之前

本章的 oracle 能抓住「測試真的走到那條路徑」時的錯誤，但有兩個明顯限制：

1. 未被目前測試向量覆蓋的路徑可能仍藏著窄化或溢位；
2. 通道守恆、端點所有權與資源不足有時在整個網路跑起來後才以等待或死結呈現。

下一章將把第二層防線加到流程中。我們會使用 `reda check` 做靜態值域分析，檢查落點、累加器、通道 token 守恆、端點所有權與硬體資源，並學習如何解讀 E0102、E0301、E0501、E0702 等診斷。

行為模擬回答「這次執行的 token 契約是否成立」；靜態檢查則嘗試回答「所有可能執行的路徑是否都安全」。兩者都通過，才形成一個足以進入 FSM 降階與硬體合成的可信起點。
