# 1.9 練習與檢核

### 練習 1.1：只寫契約，不寫程式

將「將 8 位元樣本乘以 2 並飽和輸出」改寫成 token 契約。請至少列出輸入與輸出值域、對應關係、關閉語意、背壓，以及 `x = 100` 與 `x = -100` 時的結果規則。

一個可接受的起答案是：輸入是 8 位元有號值域  $[-128,127]$ ，輸出仍為 8 位元有號值域；每個輸入 token 對應一個輸出 token，順序保持；乘積若超出輸出範圍則分別飽和到 127 或 -128；來源關閉後，運算器在沒有待處理項目時關閉輸出；有限容量通道必須尊重背壓。

### 練習 1.2：估計每拍一個 FIR 樣本的資料流量

假設 FIR 每拍接受一個樣本，列出：

1. 輸入與輸出介面各需要多少 token／拍？
2. 延遲線每拍要寫入多少個樣本，最多讀取多少個樣本？
3. 完全展開的乘法路徑需要幾組乘法器與加法器？
4. 若改成序列 MAC，哪些指標會下降，哪些資源會下降？

一個簡單的檢核答案是：外部介面各是一個 token／拍；延遲線每拍寫入一個樣本，完全展開時每拍可能讀取四個狀態值；完全展開需要四組乘法器及相應的三次加法（實作上也可能是平衡加法樹）；序列 MAC 可把乘法與加法資源降到一組，但 II 會上升到約四拍。確切數量仍取決於管線、記憶體與目標實作。

### 自我檢核

讀完本章後，請嘗試不用「更快」或「最佳化」這兩個模糊詞，描述你的 FIR 設計。你至少應該能說出：

- 一個輸入 token 的合法值域，以及輸出 token 的值域策略；
- 輸入與輸出之間的對應關係；
- 通道關閉與背壓的規則；
- 目標 II、延遲與資源限制；
- 行為模擬、合成與外部介面各自要驗證什麼。

如果其中任何一項只能用「看情況」回答，代表契約還沒有完成。下一章將把這張契約表逐步放進 Fluxa 原始碼：我們會從最小 task、通道與測試開始，讓語言成為硬體思維可執行的形式。
