# 10.4 閘級模擬的等價判準

## 10.4.1 比對什麼

閘級模擬不能只看「程式有沒有印出錯誤」。至少要比對：

1. 每個 `test` 的斷言結果；
2. 每個輸出通道的 token 序列；
3. 通道關閉的位置；
4. 邊界值與錯誤案例的退出狀態。

只有全部一致，才能說這一組測試在三層之間等價。

## 10.4.2 token 序列是核心

對串流設計而言，token 序列比個別訊號波形更能代表語意。若輸入是：

```text
1, 2, 3, 4
```

行為模型與閘級模擬都應該產生相同的輸出序列，例如：

```text
3, 6, 11, 20
```

若順序不同但集合相同，仍然不算等價。Kahn 網路的確定性保證同一通道內有順序，因此閘級模擬必須保留這個順序。

## 10.4.3 關閉與邊界

通道關閉是容易被忽略的語意。若關閉過早，接收端可能少收到 token；若關閉過晚，接收端可能永遠等待。閘級模擬應比對：

- 關閉是否發生在正確的 token 之後；
- 關閉後是否還有資料被送出；
- 接收端是否正確結束。

邊界值也同樣重要：最大整數、最小值、零、窄化邊界與飽和邊界，都是最容易暴露位寬或映射差異的地方。

## 10.4.4 差異不是「看起來可接受」

如果閘級模擬與行為模型不同，不能用「硬體本來就會有延遲」或「數值差不多」帶過。延遲可以不同，但 token 內容、順序與關閉位置必須相同。

差異應該被視為實作問題，並依序排查：

1. 是測試本身依賴了未保證的跨通道順序？
2. 是位寬推導或飽和語意在某一層不同？
3. 是合成把某個操作映射成不同的算術？
4. 是通道埠或關閉訊號接錯？

## 10.4.5 等價的範圍要寫清楚

最後，任何「等價」結論都應附上範圍：

- 跑了哪些測試；
- 用了哪些輸入與 seed；
- 比對了哪些欄位；
- 哪些行為尚未覆蓋。

沒有範圍的「已驗證」只是口號。有範圍的「這組測試在三層一致」才是可審核的工程證據。
