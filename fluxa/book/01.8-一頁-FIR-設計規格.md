# 1.8 一頁 FIR 設計規格

本章的章末產物不是程式，而是一頁可以在團隊中討論、也可以交給後續章節反覆引用的規格。下面是一個刻意保守的起點；它不是唯一正確的答案。

### FIR-4 設計規格（草稿）

**目的**  
對一串有號整數樣本套用四個固定係數，產生保持順序的濾波結果。

**資料契約**

- 輸入：一個 token 代表一個樣本；值域暫定為 16 位元有號整數，實際係數格式待第 3 章推導。
- 輸出：一個 token 代表一個濾波結果；結果型別必須容納四個乘積的累加，輸出採明確的飽和策略。
- 順序：第  $n$  個結果對應第  $n$  個輸入樣本的濾波時間點；不得重排或丟棄。
- 初始狀態：歷史視窗為零；第一個輸入也有完整結果。
- 關閉：來源關閉後，濾波器先消耗已送出的樣本，再依「完整濾波語意」送出必要的尾端結果，最後關閉輸出通道。
- 背壓：有限容量通道；來源不得忽略接收端的背壓，接收端不得假設資料永遠立即可用。

**錯誤與代價**

- 中間乘積與累加不得發生未宣告的窄化。
- 若最終結果超出輸出值域，飽和而非回繞。
- 目標為 II = 1；延遲上限與允許資源取決於目標裝置，需由合成報告確認。

**尚待驗證**

- 係數的定點格式與捨入方式。
- 關閉時究竟需要幾個 flush token。
- 通道容量與最壞情況下的緩衝延遲。

這一頁規格看起來沒有寫任何 `fn` 或 `task`，卻已經決定了元件最重要的邊界。後面的語言與工具，都是在把這張規格逐步變成可執行、可合成、可驗證的東西。
