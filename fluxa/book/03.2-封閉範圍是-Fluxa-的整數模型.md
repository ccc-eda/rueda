# 3.2 封閉範圍是 Fluxa 的整數模型

Fluxa 的一般整數型別是：

```fluxa
int<lo..=hi>
```

`..=` 表示右端也包含在內，因此這是「封閉值域」。內建的 `uN` 與 `iN` 只是常用範圍的簡寫：



$$
uN \equiv \operatorname{int}\langle 0..=2^N-1\rangle
$$





$$
iN \equiv \operatorname{int}\langle -2^{N-1}..=2^{N-1}-1\rangle
$$



例如：

```fluxa
let a: u8 = 200;       // 0..=255
let b: i8 = -100;      // -128..=127
let c: int<0..=99> = 42;
```

`int<0..=99>` 和 `u8` 都不是同一個型別語意。更精確地說，`int<0..=99>` 的**最小實體寬度**是 7 位元，但它的合法值域只有 `0..=99`；`u8` 的最小實體寬度是 8 位元，合法值域則剛好是二進位的 `0..=255`。兩者的差異在於語言允許哪些值，以及運算如何推導範圍。

這裡要分清兩個詞：

- **值域**是型別保證值可以落在哪個封閉區間內，是語意層面的契約。
- **位寬**是將該值域放入二進位儲存或運算器時所需的實體位元數，是實作層面的結果。

Fluxa 的順序是「先有值域，再算位寬」。對非負值域 `[a,b]`，最小位寬為：



$$
w=\max\left(1,\left\lceil\log_2(b+1)\right\rceil\right)
$$



對跨越負數的值域，則使用兩補數表示：



$$
w=1+\left\lceil\log_2(\max(-a,b+1))\right\rceil
$$



舉幾個例子：

| 值域 | 最小位寬 | 適合的內建型別 |
|---|---:|---|
| `0..=1` | 1 | `u1` |
| `0..=99` | 7 | `u7` 可容納，但型別仍可寫成 `int<0..=99>` |
| `0..=255` | 8 | `u8` |
| `-128..=127` | 8 | `i8` |
| `-300..=300` | 10 | `i10` |
| `-1024..=1023` | 11 | `i11` |

注意「適合的內建型別」不表示要把 `int<0..=99>` 改寫成 `u7`；前者宣告了較窄的語意，後者只宣告物理寬度。若某個值域不是標準二補數邊界，Fluxa 仍以 `int<lo..=hi>` 保留完整契約。

### 整數字面量也有一個值域

字面量 `42` 的推導型別是單點範圍：



$$
42 : \operatorname{int}\langle42..=42\rangle
$$



這讓常數參與運算時仍遵循同一套規則。例如 `3 * x` 的乘積會把 `3` 視為 `int<3..=3>`，而不是偷偷假定它是某個平台上的 32 位元整數。

### 型別化變數與推導型別變數

這兩種寫法代表不同的硬體意圖：

```fluxa
let sum = a + b;       // 由運算式推導值域與寬度
let sum: u9 = a + b;   // 明示 9 位元目標；來源可完整放入時允許
let sum: u8 = a + b;   // 危險：來源 0..=510 不能放入 0..=255
```

第一種通常最精簡：工具會依值域算出所需寬度。第二種適合介面規格已明確指定寬度的情況。第三種則會被視為窄化，必須另外表達轉換策略。
