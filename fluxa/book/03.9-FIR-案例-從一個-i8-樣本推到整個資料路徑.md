# 3.9 FIR 案例：從一個 `i8` 樣本推到整個資料路徑

現在把本章的規則應用到四階 FIR。採用可精確表示的係數：



$$
h=\left[\frac18,\frac38,\frac38,\frac18\right]
$$



Fluxa 程式如下：

```fluxa
const COEF: [fixed<1, 7>; 4] = [0.125, 0.375, 0.375, 0.125];

task Fir4(x: in chan<i8>, y: out chan<i8>) {
    let mut hist: [i8; 3] @reg = [0; 3];

    pipeline(ii = 1) for s in x {
        let win: [i8; 4] = concat([s], hist);
        let acc = (0..4).unrolled()
                           .map(|k| win[k] * COEF[k])
                           .tree_sum();
        hist = win[0..3];
        y.send(acc.to::<i8>(round = nearest, ovf = sat));
    }
}
```

以下推導先採結構型上界；常數係數的實際值域還可能更窄。

### 第一步：輸入與歷史樣本

輸入通道元素與歷史暫存器都是 `i8`：



$$
\operatorname{int}\langle-128..=127\rangle
$$



實體寬度 8 位元。

### 第二步：係數

`fixed<1,7>` 的整數位包含符號，因此共有  $1+7=8$  位元，值域為：



$$
-1..=\frac{127}{128}
$$



四個實際係數都在這個範圍內。

### 第三步：每個乘積

`i8` 可視為 `fixed<8,0>`。套用定點乘法規則：



$$
\operatorname{fixed}\langle8,0\rangle
\times
\operatorname{fixed}\langle1,7\rangle
=
\operatorname{fixed}\langle9,7\rangle
$$



因此四個乘積各為 `fixed<9,7>`，總寬 16 位元。

### 第四步：平衡加法樹

第一層將四個乘積配成兩組：



$$
\operatorname{fixed}\langle9,7\rangle
+
\operatorname{fixed}\langle9,7\rangle
=
\operatorname{fixed}\langle10,7\rangle
$$



第二層把兩個部分和相加：



$$
\operatorname{fixed}\langle10,7\rangle
+
\operatorname{fixed}\langle10,7\rangle
=
\operatorname{fixed}\langle11,7\rangle
$$



所以最終 `acc` 為 `fixed<11,7>`，總寬 18 位元。

注意平衡樹的推導不是「四個乘積就直接加三個整數位」：第一層的兩個加法各自得到 `fixed<10,7>`，第二層才形成 `fixed<11,7>`。若改用循序累加，型別增長路徑會不同，延遲與面積也會不同；這個取捨會在第 8 章進一步討論。

### 第五步：最終輸出

FIR 的係數總和為 1，輸出仍以整數樣本表示。轉換：

```fluxa
acc.to::<i8>(round = nearest, ovf = sat)
```

包含兩個明確決策：

1. `round = nearest`：從 7 個小數位縮到 0 個小數位時捨入至最近整數。
2. `ovf = sat`：若捨入後仍超出 `i8` 範圍，停在 `-128` 或 `127`。

如果介面契約其實允許模 256 回繞，才應改用 `ovf = wrap`；若超範圍是系統故障，就可在模擬中用 `check`，並另外設計硬體錯誤報告。

### FIR 位寬推導表

| 訊號 | 來源值域／型別 | 實體寬度 | 理由 |
|---|---|---:|---|
| `s`、歷史樣本 | `i8`，`-128..=127` | 8 | 輸入通道元素與 `@reg` 元素。 |
| `COEF[k]` | `fixed<1,7>`，`-1..=127/128` | 8 | 1 個含符號整數位 + 7 個小數位。 |
| `win[k] * COEF[k]` | `fixed<9,7>`，結構上界約 `-256..=255.9921875` | 16 | 整數位 `8+1`，小數位 `0+7`。 |
| 兩個乘積之和 | `fixed<10,7>`，結構上界約 `-512..=511.984375` | 17 | 對齊小數位後，加法多保一位進位。 |
| 最終 `acc` | `fixed<11,7>`，結構上界約 `-1024..=1023.9921875` | 18 | 平衡加法樹第二層再多一位。 |
| `y.send` 的值 | `i8`，`-128..=127` | 8 | 明確使用 `nearest + sat` 轉換。 |

表中的乘積與和採用固定型別本身的結構範圍，尚未利用「係數皆非負且總和為 1」進一步化簡；實際 FIR 的值域通常更窄。

若係數改用較高精度的 `fixed<1,15>`，乘積會變成 `fixed<9,15>`，加法樹末端變成 `fixed<11,15>`，總寬也隨之增加。精度不是免費的：更多小數位會增加乘積與加法器寬度，也會增加輸出捨入的時序與面積代價。

### 為什麼不能把累加器宣告成 `i8`

一個常見陷阱是：

```fluxa
let acc: i8 = /* 四個乘積的某種窄化結果 */;
```

問題不在 `tree_sum()` 本身，而在窄化發生的地方。若把完整乘積未經明確策略直接放進 `i8`，值域無法放入，工具會以 E0301 阻止。 FIR 的正確做法是讓資料路徑一路保留足夠位元，只在最後的外部介面落點做一次明確轉換。

### 另一種整數係數實作

同一組係數也能用移位實作：



$$
y[n]=(2x[n]+6x[n-1]+6x[n-2]+2x[n-3])\gg4
$$



此時乘加結果使用整數型別，最後以 `i16` 累加器保留足夠範圍，再右移 4 位並飽和到 `i8`。這種作法通常很適合小型 FPGA，但 16 位累加器比只由結構推導出的最小寬度多花一些面積。位寬推導的價值不是替工程師強迫使用最窄值，而是讓每一個額外位元都對應一項可說明的需求。
