# 11.3 案例二：3×3 影像視窗與模糊

## 11.3.1 規格

輸入是一張 `W × H` 的灰階影像，row-major 排列。輸出是每個內部像素的 3×3 視窗，或進一步做模糊：

$$
y[r][c] = \left\lfloor
\frac{
1\cdot x[r-1][c-1] + 2\cdot x[r-1][c] + 1\cdot x[r-1][c+1] +
2\cdot x[r][c-1] + 4\cdot x[r][c] + 2\cdot x[r][c+1] +
1\cdot x[r+1][c-1] + 2\cdot x[r+1][c] + 1\cdot x[r+1][c+1]
}{16}
\right\rfloor
$$

契約：

- 只輸出內部像素（`1 ≤ r ≤ H−2`、`1 ≤ c ≤ W−2`）；
- 輸出順序是 row-major；
- frame 可以重複，直到輸入關閉；
- 邊界像素的行為必須明確（略過或補齊）。

## 11.3.2 使用標準庫 `Window3x3`

Fluxa 標準庫提供 `std::Window3x3::<W, H, PW>(x, w)`：

- `x`：`in chan<uPW>`；
- `w`：`out chan<[[uPW; 3]; 3]>`；
- 只使用兩條各 `W` 個像素的 line buffer 與一個滑動視窗。

```fluxa
task Blur(w: in chan<[[u8; 3]; 3]>, y: out chan<u8>) {
    for v in w {
        y.send((v[0][0] + 2*v[0][1] + v[0][2]
              + 2*v[1][0] + 4*v[1][1] + 2*v[1][2]
              + v[2][0] + 2*v[2][1] + v[2][2]) >> 4);
    }
}

task Blur8x6(x: in chan<u8>, y: out chan<u8>) {
    let (tw, rw) = chan::<[[u8; 3]; 3]>(depth = 2);
    spawn std::Window3x3::<8, 6, 8>(x, tw);
    spawn Blur(rw, y);
}
```

## 11.3.3 權重和的位寬

上式的權重和最大為：

$$
1+2+1+2+4+2+1+2+1 = 16
$$

每個像素最大為 `255`，所以總和最大為：

$$
16 \times 255 = 4080
$$

這需要 12 位元。若用 8 位元累加，會在亮區溢位。因此後處理 task 的內部累加型別應至少為 `u12` 等價的範圍，最後才右移四位並窄化回 `u8`。

標準庫文件也提醒：呼叫端要明確處理權重和的位寬，而不是假設 `u8` 一定夠。

## 11.3.4 line buffer 的資源

`Window3x3` 使用兩條長度 `W` 的 line buffer。對寬度 1920 的影像，這會是大量儲存；是否映射成 block RAM，取決於存取形式與目標裝置。合成報告應該顯示：

- line buffer 使用了多少 BRAM 或 FF；
- 3×3 視窗暫存器數量；
- 後處理 task 的算術面積。

若 BRAM 不足，可以考慮：

- 降低解析度或分塊處理；
- 使用較小的 `PW`；
- 把部分運算移到 frame 邊界之外。

## 11.3.5 測試

測試應包含：

- 單一 frame 與重複 frame；
- 全黑、全白與棋盤格；
- 寬度或高度小於 3 的邊界情況（應明確拒絕或定義行為）；
- 關閉時是否輸出正確數量的像素。

## 11.3.6 交付摘要

| 欄位 | 內容 |
| --- | --- |
| 頂層 | `Blur8x6` 或參數化的 `BlurWxH` |
| 介面 | `x: chan<u8>`、`y: chan<u8>` |
| 型別 | line buffer `u8`、權重和至少 12 位元 |
| 資源 | 兩條 line buffer、9 個視窗暫存器 |
| 驗證 | 正常、邊界、重複 frame |
| 已知限制 | 影像邊界策略需在契約中明說 |
