# Fluxa 模擬器 v0.2

日期：2026-10-29

v0.1 之後的變更：**多檔載入**、新增 **RV32I 處理器範例**、以及配套的 rv32i 測試修復。
行為語意（KPN 確定性、線性端點、120 位元算術等）與 v0.1 完全相同，未有任何改動。

## 1. 多檔載入（新功能）

CLI 比照 `iverilog a.v b.v`，接受多個 `.fx` 檔，定義合併後執行：

```
./target/release/fluxa a.fx b.fx          # 兩檔合併成一個程式
./target/release/fluxa a.fx b.fx --list   # --list / --test 看到的是合併後的程式
```

- 合併規則：`const` 宣告依檔案順序收集；`test` 依序收集；
  **函式／task 名稱不可跨檔重複**，重複即載入錯誤（exit 2）。
- 測試檔可以只寫 `test` 區塊，被測的 DUT 與 harness 函式放在另一檔
  （見 `fluxa rv32i/rv32i.fx rv32i/tests_basic.fx`）。

程式庫與實作變更：

- 新增 `fluxa::load_many(files: &[(String, String)])`；`load` 改為其單檔包裝，舊程式碼不受影響。
- `Program` 由單一 `file: String` 改為 `files: Vec<String>`。
- 錯誤行號把**檔案編號**編進高位：行號 = `file_idx * ast::FILE_STRIDE + 原行號`
  （`FILE_STRIDE` = 1_000_000）。顯示一律經 `Program::loc(line)` 還原成 `檔名:行號`；
  直接比較或印出原始行號會得到錯誤位置。
- `lexer::lex_from(src, line_base)`、`parser::parse_program_at(file, src, file_idx)` 為對應的底層入口。

## 2. RV32I 處理器範例（新範例）

`rv32i/` 以 Fluxa 實作一顆 RV32I 核心與測試（`./rv32i.sh` 一鍵執行）：

| 檔案 | 內容 |
|---|---|
| `rv32i.fx` | 核心：`Fetch` → `Decode` → `Execute` → `Mem` 四個 task 以深度 1 的 FIFO 相連；Decode 持有暫存器檔與記分板（資料相依停等寫回），分支/JALR 由 Execute 送回 redirect token（停等，無分支預測）。另含組譯器函式（`addi`/`lw`/`beq`/…，參數型別即欄位寬度，超界立即值在組譯時就被擋下）、解碼 `comb fn`、`Core::<WBD>` 頂層與 `run`/`run_with` 測試 harness |
| `smoke.fx` | 1 個煙霧測試（`smoke_sum`） |
| `tests_basic.fx` | 24 個測試：ALU、分支、跳轉、load/store 位元組通道、資料相依停等、MMIO 輸出、軟體乘法、氣泡排序、陷阱行為等 |
| `err_bad_immediate.fx` | 預期失敗：`addi` 立即值 3000 超出 i12（組譯期位寬檢查） |
| `err_wb_depth.fx` | 預期失敗：`Core::<1>` 寫回 FIFO 太淺 → 死結，模擬器報出每個階段卡在哪條通道 |

```
./rv32i.sh                                             # smoke + tests_basic，全數通過
./target/release/fluxa rv32i/rv32i.fx rv32i/err_wb_depth.fx    # 必須回報 deadlock（exit 1）
./target/release/fluxa rv32i/rv32i.fx rv32i/err_bad_immediate.fx  # 必須回報 does not fit i12
```

`err_*.fx` 為預期失敗示範，不在 `rv32i.sh` 內，需手動對 `rv32i.fx` 執行。

## 3. 修復

- **MMIO 輸出導致的死結**：`run_with` harness 原本 `io` 通道深度為 4，
  但測試端會先把 36 個 dump token 收完才收 `io`；程式的 MMIO 輸出超過 4 個時
  （如 fibonacci 輸出 10 個），`Mem` 會在抵達 ECALL 前卡滿 → 全線死結。
  現改為 `depth = FETCH_LIMIT`：MMIO 寫入次數 ≤ 已發射指令數 ≤ FETCH_LIMIT，是可證明的上界。
  （輸出 token 序列本就與 FIFO 深度無關，此變更不影響結果，只影響是否卡死。）
- **`tests_basic.fx` 檔尾殘留**：先前以 shell heredoc 寫檔時留下的
  `EOF` / `cat > err_wb_depth.fx <<'EOF'` 與誤併入的 `undersized_writeback_fifo` 測試，
  已移除；該測試歸位到獨立的 `err_wb_depth.fx`。
