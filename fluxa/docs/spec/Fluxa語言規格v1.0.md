# Fluxa 語言規格 v1.0

版本 1.0｜2026-11-21｜狀態：與實作一致（rueda 0.7.0）。v0.1 是實作前的設計草案；v1.0 取代它。

本文件面向 Fluxa 程式設計者，以及撰寫、檢查或合成 Fluxa 程式的 AI agent。本文件以 `reda sim`、`reda emu`、`reda check` 與 `reda synth/fpga/asic/gatesim` 的現有實作為準。

## 0. 本版說明：v0.1 → v1.0 主要變化

| 類別 | 主要變化 |
| --- | --- |
| 已實作且與 v0.1 一致 | 整數以封閉範圍表示；加、減、乘、移位、除法與取模可推導值域；`task` 與有界通道形成 Kahn 程序網路；`carry` 與型別化累加器可做靜態溢位分析；`@reg` 在迭代結束時提交寫入；`pipeline(ii = n)`、`unroll`、`serial` 可由合成器處理。 |
| 改變 | `+%`、`-%`、`*%` 仍以左運算元的型別回繞，但左運算元現在必須是具有「已宣告型別」的變數；型別參數可在模擬中使用，但不能合成，必須改用 const 泛型表達元素位寬；使用 `std::` 時，標準庫會自動併入程式，使用者定義優先，且命名空間最後一段就是實際名稱。 |
| 新增 | 模擬器以精確 120 位元整數計算；`reda check` 以區間分析檢查窄化、累加、索引、通道守恆與端點所有權；`reda emu` 提供編譯後執行；通道參數的元素型別必須完全相符；多個 `.fx` 檔可合併成同一程式。 |
| 保留未實作 | `stage` 層、`iface`、`schedule`、Graph API、bank 分割、完整的 SDF 最小 FIFO 深度分析、`assume`、以函式作為平行樣式參數，以及 v0.1 所列但尚未實作的標準庫模組。完整清單見 §14。 |

v0.1 中尚未實作的設計不得視為 v1.0 的語言保證。特別是，`stage`、`iface` 與 `schedule` 雖可被前端的解析器接受或略過，但目前沒有 v0.1 所述的硬體語意。

## 1. 詞法

### 1.1 識別字、註解與路徑

| 類別 | 規則 |
| --- | --- |
| 識別字 | `[A-Za-z_][A-Za-z0-9_]*` |
| 單行註解 | `//` 至行尾 |
| 區塊註解 | `/* ... */`；區塊可巢狀 |
| 路徑 | `IDENT` 或以 `::` 分隔的 `IDENT::IDENT...` |
| 泛型實例 | `::<...>`，如 `Task::<4, 8, 32>(...)` |

### 1.2 字面量

| 類別 | 形式 |
| --- | --- |
| 十進位整數 | `42` |
| 十六進位整數 | `0xFF` |
| 二進位整數 | `0b1010_0101` |
| 底線 | 可用於數字各位之間，如 `1_000`；不得改變數值 |
| 定寬整數 | `8'hFF`、`4'b1010`、`12'd100`；型別分別為 `u8`、`u4`、`u12` |
| 定點整數 | `0.75`；其固定點型別須由型別註記或上下文決定 |
| 布林值 | `true`、`false` |
| 訊息字串 | `"..."`，用於 `assert` 的可選訊息 |

整數運算與值域推導以整數值為基礎；定點字面量不是浮點數。

### 1.3 範圍

| 形式 | 意義 |
| --- | --- |
| `a..b` | 右開範圍，包含 `a`，不包含 `b` |
| `a..=b` | 右閉範圍，包含 `a` 與 `b` |

### 1.4 關鍵字

下列關鍵字會直接影響解析或語意：

`const`、`fn`、`comb`、`comptime`、`task`、`test`、`let`、`mut`、`carry`、`for`、`in`、`if`、`else`、`match`、`spawn`、`parallel`、`pipeline`、`unroll`、`serial`、`assert`、`return`、`chan`、`mem`、`fixed`、`int`、`bits`、`bit`、`bool`、`true`、`false`。

下列項目目前的處理方式如下：

| 項目 | 現行處理 |
| --- | --- |
| `use` 宣告 | 解析後略過，不建立匯入別名。 |
| `type` 宣告 | 解析後略過，不建立型別別名。 |
| `iface` 項目 | 解析後略過，不產生介面語意。 |
| `schedule` 項目 | 解析後略過，不產生排程語意。 |
| `stage` 項目 | 明確報錯；診斷包含 `not supported`。 |

`depth`、`round`、`ovf`、`reg` 等名稱在特定語法位置具有上下文意義，不是可隨意使用的保留字。

### 1.5 運算子與標點

Fluxa 使用下列運算子：

- 算術：`+`、`-`、`*`、`/`、`%`
- 明確回繞：`+%`、`-%`、`*%`
- 位元：`&`、`|`、`^`、`~`、`<<`、`>>`
- 比較：`==`、`!=`、`<`、`<=`、`>`、`>=`
- 布林：`&&`、`||`、`!`
- 型別轉換：`as`
- 其他：賦值、複合賦值、`::`、turbofish `::<...>`、`@`、括號、方括號與大括號

運算子優先序由高至低為：

1. 後綴運算
2. 一元運算
3. `as`
4. `*`、`/`、`%`、`*%`
5. `+`、`-`、`+%`、`-%`
6. `<<`、`>>`
7. `&`
8. `^`
9. `|`
10. 比較
11. `&&`
12. `||`
13. 範圍

## 2. 程式結構與項目

### 2.1 頂層項目

一個 Fluxa 程式由零或多個頂層項目組成。可實作的項目如下：

| 項目 | 形式 | 意義 |
| --- | --- | --- |
| 常數 | `const NAME: T = expr;` | 在編譯期求值。 |
| 一般函式 | `fn NAME(params) [-> T] { ... }` | 無狀態函式；可回傳宣告型別的值。 |
| 組合函式 | `comb fn NAME(params) -> T { ... }` | 合成時展開為組合邏輯的函式。 |
| 編譯期函式 | `comptime fn NAME(params) [-> T] { ... }` | 在編譯期執行的函式。 |
| 任務 | `task NAME(params) [-> T] { ... }` | 可與其他任務並行執行的程序。 |
| 測試 | `test NAME { ... }` | 一個可獨立執行的測試程序。 |

`fn`、`comb fn`、`comptime fn` 與 `task` 的參數以逗號分隔。通道參數可標示 `in` 或 `out`：

- `in chan<T>`：參數接收通道的接收端。
- `out chan<T>`：參數接收通道的傳送端。

`test` 區塊可建立通道、啟動任務、傳送與接收 token，並以 `assert` 驗證結果。

### 2.2 泛型項目

任務可宣告 const 泛型參數：

```text
task NAME<const N: u32>(...) { ... }
```

const 泛型參數在編譯期求值，可出現在型別、陣列長度、通道元素型別及任務呼叫的 turbofish 實例化中，例如 `Task::<4, 8, 32>(...)`。

任務也可宣告型別參數：

```text
task NAME<T>(...) { ... }
```

型別參數可由模擬器處理，但目前不能合成。需要合成的泛型元件應以 const 泛型表達固定位寬或固定大小；例如 AW 位元有號整數可寫成：

```text
int<-(1 << (AW - 1)) ..= (1 << (AW - 1)) - 1>
```

### 2.3 多檔合併

數個 `.fx` 檔可像 `iverilog a.v b.v` 一樣合併成同一程式：

```sh
reda sim first.fx second.fx
```

合併後的所有使用者項目共用一個全域命名空間，因此使用者檔案中的名稱必須唯一；重複的函式、任務、測試或常數名稱均視為名稱衝突。

各檔案內的測試都屬於合併後的程式，可用 `--test NAME` 選取其中一項。

### 2.4 標準庫載入與名稱解析

只有當程式來源中含有 `std::` 時，載入器才會把 `fluxa/sim/std/std.fx` 合併到使用者檔案之後。

名稱解析規則如下：

1. 使用者自己的定義優先於同名標準庫定義。
2. `std::Name` 與 `Name` 指向同一項目；`std::` 前綴不建立另一個獨立名稱。
3. 多段名稱以最後一段作為實際名稱，例如 `std::dsp::Name` 的實際名稱為 `Name`。
4. 使用者檔案之間仍須遵守名稱唯一規則；使用者定義覆蓋標準庫同名項目不視為使用者檔案間的重複。

標準庫並非黑盒 IP；其中的任務使用 Fluxa 本身實作，因此可參與模擬、靜態檢查、合成與閘級模擬。

## 3. 型別

### 3.1 整數範圍型別

一般整數型別為：

```text
int<lo..=hi>
```

`lo` 與 `hi` 是編譯期整數常數，表示型別可容納的最小值與最大值。

內建整數別名為：

| 型別 | 等價範圍 | 條件 |
| --- | --- | --- |
| `uN` | `int<0..=2^N-1>` | $N \ge 1$ |
| `iN` | `int<-2^(N-1)..=2^(N-1)-1>` | $N \ge 1$ |

因此：

```text
i8 = int<-128..=127>
u8 = int<0..=255>
```

整數值域是型別的一部分。兩個整數值域相同但寫法不同的型別，例如 `i8` 與 `int<-128..=127>`，具有相同的值域語意。

### 3.2 位元與布林型別

| 型別 | 意義 |
| --- | --- |
| `bit` | 單一位元值，不帶整數算術語意。 |
| `bool` | 布林值，只能由布林條件式邏輯使用。 |
| `bits<N>` | 固定寬度為 $N$ 的位元向量，不帶整數算術語意。 |

`bit` 與 `bool` 在語意上不同；布林運算的結果為 `bool`，位元操作的結果仍為 `bit` 或 `bits<N>`。

### 3.3 定點型別

定點型別形式如下：

```text
fixed<I, F, round = trunc | nearest | even, ovf = wrap | sat | check>
```

其中：

- $I$ 是整數部分的位元總數，包含符號位。
- $F$ 是小數部分的位元數。
- `trunc` 直接截去被捨去的位元。
- `nearest` 捨入至最近值。
- `even` 在恰好 halfway 時捨入至偶數。
- `wrap` 超出目標範圍時回繞。
- `sat` 超出目標範圍時飽和至上下界。
- `check` 在溢出時使模擬失敗；硬體中不因此產生額外邏輯。

`iN` 可視為 `fixed<N, 0>`。

### 3.4 複合型別

| 型別 | 意義 |
| --- | --- |
| `[T; N]` | 長度為 $N$ 的陣列，元素型別為 `T`。 |
| `(T1, T2, ...)` | tuple；各位置可有不同型別。 |
| `chan<T>` | 元素型別為 `T` 的通道。 |

陣列長度為編譯期常數。tuple 可作為通道 token；其元素型別分別受型別檢查與落點檢查約束。

通道的 `in`、`out` 方向由任務參數宣告，而不是另立的 `Tx<T>`、`Rx<T>` 型別。通道實例以 `chan::<T>(depth = d)` 建立，其中 `d` 是 FIFO 深度。

### 3.5 記憶體

記憶體型別為：

```text
mem<T, N>
```

`T` 是元素型別，`N` 是元素數量。記憶體以 `m[i]` 形式存取。

在合成時，若記憶體只以簡單的索引讀寫形式使用，會映射為 block RAM；其他使用形式可能退回暫存器陣列並產生警告。記憶體的硬體實作限制見 §12。

### 3.6 `@reg` 放置

`@reg` 可放在變數宣告之後：

```text
let mut value: T @reg = initial;
```

其迭代語意為：

- 同一迭代內讀取 `@reg` 變數時，看到的是該迭代開始時的舊值。
- 迭代內的寫入在迭代結束時提交。
- 下一迭代才看到已提交的新值。

此語意使陣列移位暫存器等硬體結構可直接對應到 Fluxa 程式。

### 3.7 泛型元素型別

需要依泛型參數決定整數位寬時，使用 const 泛型計算範圍。例如 AW 位元有號整數的範圍是：

$$
\operatorname{int}\left\langle
-\left(1\ll(AW-1)\right)
\ ..=\
\left(1\ll(AW-1)\right)-1
\right\rangle
$$

CW 位元有號整數的輸出通道使用相同形式，將 `AW` 換成 `CW`。這種寫法可由模擬與合成處理；直接以型別參數代表元素寬度則只能模擬。

## 4. 運算與位寬推導

### 4.1 整數值域規則

令：

$$
e_1 : \operatorname{int}\langle a..=b\rangle,\qquad
e_2 : \operatorname{int}\langle c..=d\rangle
$$

整數值的推導規則如下：

$$
\begin{aligned}
(T\text{-}ADD)\quad
e_1+e_2
&:\operatorname{int}\langle a+c..=b+d\rangle \\[2mm]
(T\text{-}SUB)\quad
e_1-e_2
&:\operatorname{int}\langle a-d..=b-c\rangle \\[2mm]
(T\text{-}MUL)\quad
e_1e_2
&:\operatorname{int}\langle
\min P..=\max P
\rangle,\quad
P=\{ac,ad,bc,bd\} \\[2mm]
(T\text{-}SHL)\quad
e_1\ll k
&:\operatorname{int}\langle a2^k..=b2^k\rangle \\[2mm]
(T\text{-}SHR)\quad
e_1\gg k
&:\operatorname{int}\langle
\lfloor a/2^k\rfloor..=\lfloor b/2^k\rfloor
\rangle
\end{aligned}
$$

其中 $k$ 必須是常數。

除法與取模要求除數的推導範圍不包含零：

$$
0\notin[c,d]
$$

否則產生 E0102。除法結果的值域由可能的商推導；取模結果的保守幅度界限為：

$$
\operatorname{int}\left\langle
0..=\max(|c|,|d|)-1
\right\rangle
$$

實際值由模擬器精確計算，合成器則由值域推導所需位寬。

整數字面量 $n$ 的型別為：

$$
(T\text{-}LIT)\qquad n:\operatorname{int}\langle n..=n\rangle
$$

### 4.2 模擬器與合成器的精度

- `reda sim` 使用精確的 120 位元整數進行運算，再於值的落點檢查型別範圍。
- `reda emu` 與硬體合成依照相同的值域規則推導位寬。
- 合成結果不得因位寬推導而改變 token 序列或整數值。

### 4.3 定點運算

令：

$$
e_1:\operatorname{fixed}\langle I_1,F_1\rangle,\qquad
e_2:\operatorname{fixed}\langle I_2,F_2\rangle
$$

定點加法與乘法規則為：

$$
\begin{aligned}
(T\text{-}FADD)\quad
e_1+e_2
&:\operatorname{fixed}
\langle
\max(I_1,I_2)+1,\ \max(F_1,F_2)
\rangle \\[2mm]
(T\text{-}FMUL)\quad
e_1e_2
&:\operatorname{fixed}
\langle
I_1+I_2,\ F_1+F_2
\rangle
\end{aligned}
$$

定點轉換使用 `.to::<T>(round = r, ovf = o)`。`round` 決定捨入方式，`ovf` 決定超出目標範圍時是回繞、飽和還是檢查。

### 4.4 明確回繞運算子

`+%`、`-%`、`*%` 的結果型別等於左運算元的型別，並依該型別的位寬回繞。

但實作要求左運算元必須是「具有已宣告型別的變數」。以下形式合法：

- `let x: T = ...`
- `let mut x: T = ...`
- `carry x: T = ...`
- 具有參數型別的函式或任務參數

以下形式不合法：

- `let x = a + b` 中的推導型別左變數
- `for v in rx` 中的推導型別迴圈變數
- 以一般運算式作為左運算元

模擬與合成都會產生下列錯誤：

```text
wrapping operators need a typed variable on the left; use `.wrap::<T>()` otherwise
```

若需要回繞任意運算式，應明確使用 `.wrap::<T>()`。

### 4.5 轉換

| 寫法 | 語意 |
| --- | --- |
| `e.wrap::<T>()` | 取低 $N$ 位元，以目標整數型別的兩補數表示解讀。 |
| `e.sat::<T>()` | 將值飽和至目標型別的最小值或最大值。 |
| `e.to::<T>(round = r, ovf = o)` | 使用指定的捨入與溢出策略轉換為 `T`；常用於定點型別。 |
| `e as T` | 整數型別之間的顯式轉換；不同於 `.to`，不提供 `round` 與 `ovf` 參數。 |

對整數 `T` 使用 `.to::<T>(...)` 時，其語意等同先轉成 `fixed<N, 0, ...>` 再轉回 `T`。

### 4.6 位元切片與索引

| 寫法 | 結果 |
| --- | --- |
| `x[hi:lo]` | 取得第 `hi` 至第 `lo` 位；兩端均包含。 |
| `x[i]` | 取得第 `i` 位。 |

位元切片的結果寬度為 `hi - lo + 1`；單一位元索引產生一位元結果。索引越界由模擬器與 `reda check` 診斷。

## 5. 窄化、落點與 carry

### 5.1 值的落點

下列位置是型別範圍的落點：

| 落點 | 例子 |
| --- | --- |
 | 型別化 `let` 初始值 | `let x: T = expr` |
| 賦值 | `x = expr` |
| 複合賦值 | `x += expr` |
| 通道傳送 | `tx.send(expr)` |
| 函式或任務引數 | `f(expr)` |
| 回傳值 | `return expr` |
| 陣列元素 | `a[i] = expr` |

若來源值域不能放入落點型別的完整範圍，就是窄化錯誤。值域可以放入時可自動放大；不能放入時必須明確選擇 `.wrap::<T>()`、`.sat::<T>()` 或適當的 `.to` 轉換。

### 5.2 執行期窄化診斷

`reda sim` 與 `reda emu` 在執行到窄化時產生 E0301。訊息形式為：

```text
value V does not fit T (range …)
```

例如目標型別是 `u8`，而實際值是 `300` 時，該值不能放入 `0..=255`。

### 5.3 靜態落點檢查

`reda check` 以區間分析推導每個落點的值域，不需執行測試即可發現 E0301。分析涵蓋：

- `let` 初始值
- 賦值與複合賦值
- `send`
- 函式與任務引數
- 回傳值
- 陣列元素

檢查結果包含來源範圍、目標型別，以及可容納該範圍的最小整數型別。分析採保守方式；無法證明的值域不應被當成已通過檢查。

### 5.4 `carry` 與型別化累加器

`carry` 宣告具有明確型別的累加器：

```text
carry x: T = initial;
```

在迴圈中，`x += increment` 的最終值域依下列規則推導。設初始值域為 $[a,b]$，第 $s$ 個累加點的增量值域為 $[\ell_s,h_s]$，該點的迴圈次數上界為 $N_s$，則：

$$
R=
\left[
a+\sum_s N_s\min(\ell_s,0),\ 
b+\sum_s N_s\max(h_s,0)
\right]
$$

`R` 必須完整包含於 `T` 的範圍；否則 `reda check` 產生 E0301，並列出所需的最小型別。

具有已宣告型別的 `let mut` 累加器以相同方式檢查：

```text
let mut total: T = initial;
```

推導時考慮初值、每次增量、增量所在迴圈次數，以及巢狀迴圈次數上界的乘積。

### 5.5 非加法自我更新

乘法、移位等非加法自我更新不linearize成整個迴圈。對下列形式：

```text
x = x << 1;
```

檢查器只要求這一步的結果能放入 `x` 的型別。使用者若要允許反覆更新後才超出，必須改用明確的回繞或飽和操作。

## 6. 陳述式與控制

### 6.1 變數與賦值

| 陳述式 | 意義 |
| --- | --- |
| `let x = expr;` | 宣告不可變變數並推導型別。 |
| `let x: T = expr;` | 宣告具有指定型別的變數。 |
| `let mut x = expr;` | 宣告可變變數；型別仍由初始值推導。 |
| `let mut x: T = expr;` | 宣告具有指定型別的可變變數。 |
| `carry x: T = expr;` | 宣告可用於迴圈攜帶分析的累加器。 |

賦值支援：

`=`、`+=`、`-=`、`*=`、`&=`、`|=`、`^=`、`<<=`、`>>=`。

對不可變變數賦值，或在未宣告 `mut` 時修改變數，都是型別錯誤。

### 6.2 `for` 迴圈

| 形式 | 迭代內容 |
| --- | --- |
| `for i in a..b { ... }` | 依次迭代整數 `a` 到 `b-1`；上限不包含在內。 |
| `for x in array { ... }` | 依次迭代陣列元素。 |
| `for v in rx { ... }` | 接收通道中的 token，直到通道關閉且已無待收 token。 |

迴圈可帶下列屬性：

| 屬性 | 意義 |
| --- | --- |
| `pipeline(ii = n)` | 要求迴圈以指定的啟動間隔進行管線化。 |
| `unroll` | 要求在合成時展開迴圈。 |
| `serial` | 要求以循序狀態實作，每輪形成明確的時序邊界。 |

範圍物件也可透過 `.unrolled()` 要求展開，例如對 `0..N` 呼叫 `.unrolled()`。

### 6.3 條件與分支

`if/else` 的形式為：

```text
if condition {
    ...
} else {
    ...
}
```

條件必須為布林型別。`else` 可接另一個 `if`，形成條件鏈。

### 6.4 `match`

`match` 可比對下列模式：

| 模式 | 意義 |
| --- | --- |
| 字面量 | 與相同值比對。 |
| 範圍 | 與範圍內的值比對。 |
| `_` | 比對所有剩餘情況。 |
| 綁定名稱 | 將比對到的值綁定至新變數。 |
| tuple | 逐位置比對 tuple。 |

### 6.5 `spawn` 與 `parallel`

`spawn` 啟動任務。其運算式必須是任務呼叫：

```text
spawn TaskName(args);
```

傳給任務的通道端點會轉移給該任務；呼叫端點所有權規則見 §7。

`parallel { A(…); B(…); }` 同時啟動區塊裡的每個任務呼叫，**等它們全部結束**才繼續往下執行；區塊裡只能是任務呼叫（其他陳述式是錯誤：`` `parallel` blocks may only contain task calls ``）。`spawn` 則不等待：被啟動的任務與呼叫端並行，直到它自己結束。

### 6.6 `assert`

斷言可寫成：

```text
assert condition;
```

或：

```text
assert condition, "message";
```

條件為假時，測試失敗；`reda sim` 與 `reda emu` 以非零結束碼表示測試失敗。

### 6.7 `return`

`return` 結束目前的函式或任務。若函式或任務具有回傳型別，回傳值必須符合該型別，並受 §5 的落點檢查約束。

### 6.8 Lambda

Lambda 的語法為：

```text
|identifier| expression
```

目前 lambda 只能使用於支援它 的內建操作，例如 `array` 與 `map`。函式或任務本身尚不能作為一般值傳給其他函式或任務。

## 7. 通道與任務（Kahn 程序網路）

### 7.1 執行模型

每個 `task` 都是一個獨立程序。任務可透過通道傳送 token，連接後形成 Kahn 程序網路。

通道是有界 FIFO：

- 同一通道中的 token 保持傳送順序。
- FIFO 深度只影響阻塞與吞吐，不應改變 token 的邏輯序列。
- 任務的實際排程順序不應改變結果。

### 7.2 通道操作

| 操作 | 行為 |
| --- | --- |
| `tx.send(value)` | 將 token 放入 FIFO；若 FIFO 已滿，傳送端阻塞。 |
| `rx.recv()` | 取出 FIFO 最前面的 token；若 FIFO 為空，接收端阻塞。 |
| `tx.close()` | 關閉傳送端；之後不能再傳送新 token。 |

`rx.try_recv()`、`rx.empty()`、`rx.len()` 會看到「此刻」FIFO 的狀態，結果取決於排程，破壞 Kahn 的確定性，所以在 task 層的程式裡是錯誤（`` `try_recv` is non-deterministic and is only allowed in `stage` code ``）；它們保留給尚未實作的 `stage` 層（§14）。

接收端執行 `for v in rx` 時，會先取完已送入的 token，再於觀察到通道關閉後結束迴圈。

### 7.3 端點所有權

通道端點是線性資源。`chan::<T>(depth = d)` 建立傳送端與接收端；端點不可複製，也不可在使用後繼續保留。

將端點傳給 `spawn` 的任務會移動端點所有權。例如：

```text
spawn Worker(rx, tx);
```

執行後，呼叫端不得再使用 `rx` 或 `tx`。

違反此規則時：

- `reda check` 產生 E0702。
- 模擬器在執行到違規使用時產生 E0702，執行期訊息包含：

```text
task does not own the rx endpoint
```

`broadcast` 同樣會消耗其來源接收端。

### 7.4 任務的通道參數

通道參數的方向與元素型別都必須相符：

| 參數 | 所需端點 |
| --- | --- |
| `in chan<U>` | 元素型別為 `U` 的接收端 |
| `out chan<U>` | 元素型別為 `U` 的傳送端 |

`U` 必須與通道的實際元素型別完全相符；僅型別相容或值域包含關係不足。

模擬器在 `spawn` 時檢查此條件。例如，通道攜帶 `i8`，但任務參數宣告為 `chan<i16>` 時，診斷為：

```text
the channel `c` carries i8, the parameter is chan<i16>
```

硬體合成在網路連線時執行相同檢查。

### 7.5 `broadcast`

`broadcast(rx, n)` 消耗來源接收端 `rx`，並建立 $n$ 個接收端。每個接收端都會收到來源通道中的每個 token，因此：

- 各接收端看到相同的 token 序列。
- 一個接收端的消費速度不會使其他接收端遺失 token。
- 來源接收端在呼叫後不可再使用。

### 7.6 死結

若所有仍可執行的任務都因通道操作而阻塞，模擬器判定為死結，產生 E0701。診斷會列出：

- 哪些任務仍存活；
- 每個任務正在等待哪個通道；
- 通道位於哪個任務的哪個端點。

死結使受影響的測試失敗。`reda check` 可在部分有限執行模型中，以通道 token 守恆提前發現會導致死結的網路。

### 7.7 確定性

Fluxa 的語意是 Kahn 程序網路語意。在沒有死結的情況下：

- 相同的 token 輸入產生相同的邏輯輸出序列；
- FIFO 深度只影響阻塞時間與吞吐；
- 執行緒式排程器與合作式排程器必須得到相同結果；
- 行為模擬、編譯後模擬及可合成的閘級模擬必須對相同測試得到一致結果。
## 8. 內建函式與方法

內建函式與方法仍須遵守第 3～7 節的型別、窄化、通道及端點所有權規則。

### 8.1 全域內建函式

| 函式 | 語義 |
| --- | --- |
| `abs(x)` | 回傳 `x` 的絕對值。 |
| `min(a, b)`、`max(a, b)` | 回傳兩個可比較值中較小或較大的值。 |
| `array(n, \|i\| ...)` | 建立長度為 `n` 的陣列，依序以索引呼叫回呼。回呼可建立通道端點組等值。 |
| `broadcast(rx, n)` | 將 `rx` 交給廣播器，建立 `n` 個接收端；來源通道的每個 token 都會送至每個接收端。 |
| `chan::<T>(depth = d)` | 建立元素型別為 `T`、容量為 `d` 的通道，並回傳 `(tx, rx)` 端點組。 |
| `concat(a, b)` | 依參數順序串接陣列，結果為兩陣列長度相加的陣列。 |
| `zip(a, b)` | 將兩個 iterable 的對應元素組成 tuple 陣列。 |
| `design_lowpass(taps = n, cutoff = c, window = w)` | 產生低通 FIR 係數陣列；視窗 `w` 可為 `hamming`、`hann` 或 `rect`。 |
| `print(x)` | 在模擬器或編譯模擬器輸出值。硬體合成時此呼叫被丟棄，不產生邏輯。 |
| `len(x)` | 回傳陣列 `x` 的元素數。 |

### 8.2 陣列與值的方法

| 方法 | 語義 |
| --- | --- |
| `x.len()` | 回傳陣列長度。 |
| `x.iter()` | 依序取得陣列元素。 |
| `x.enumerate()` | 依序取得元素及其索引。 |
| `x.rev()` | 以相反順序取得元素。 |
| `x.map(\|v\| ...)` | 將函式或 lambda 套用到各元素。 |
| `x.collect()` | 將迭代結果收集為陣列。 |
| `x.sum()` | 將所有元素相加。 |
| `x.tree_sum()` | 以平衡加法樹計算總和；硬體合成展開成加法樹，而非依序累加器。 |
| `range.unrolled()` | 將靜態有界的範圍標記為展開迴圈；模擬時結果不變，合成時產生各迭代的邏輯。 |
| `x.popcount()` | 非負整數 `x` 的二進位表示中 `1` 的個數。 |
| `x.xor_reduce()` | 非負整數 `x` 所有位元的 XOR（同位位元，0 或 1）。 |
| `x.abs()` | 回傳絕對值。 |
| `x.quantize::<T>()` | 將值量化為指定的定點型別 `T`，使用 `T` 所指定的捨入規則。 |
| `x.to::<T>(round = r, ovf = o)` | 轉換為 `T`；`r` 可為 `trunc`、`nearest` 或 `even`，`o` 可為 `wrap`、`sat` 或 `check`。 |
| `x.sat::<T>()` | 將值飽和至 `T` 的範圍。 |
| `x.wrap::<T>()` | 保留 `T` 所需的低位元，並依 `T` 使用二補數語意。 |

### 8.3 通道方法

| 方法 | 語義 |
| --- | --- |
| `tx.send(value)` | 送出 `value`。若通道已滿，呼叫端阻塞至有空間為止。 |
| `rx.recv()` | 接收一個 token；若通道為空，呼叫端阻塞至有 token 為止。 |
| `tx.close()` | 關閉通道的送端。已進入 FIFO 的 token 仍可接收，之後的迭代才會在通道關閉且清空時結束。 |

## 9. comptime 與泛型

泛型可分成 const generic 與 type generic。兩者在模擬器中的行為不同：

- **Const generic** 在編譯期求值，可用於通道深度、陣列長度、迴圈次數及硬體常數。const generic task 以 `::<...>` 明確指定引數，例如 `spawn Worker::<4>(...)`。
- **Type generic** 參數如 `<T>` 可在模擬器中使用，但合成器不能為其產生硬體。合成時必須改用 const generic 表達元素位寬。

`comptime fn` 是在編譯期執行的函式，不得讀取執行期值，並應回傳封閉值。一般 const 也可由 comptime 區塊求得：

```rust
const SIZE: u32 = 4;
const VALUE: i16 = comptime { SIZE * 2 };
```

會建立通道的 task 可在靜態迴圈中建立固定形狀的任務網路。例如：

```rust
let cs = array(n, |_| chan::<i8>(depth = d));
```

所得 `cs[i]` 是通道端點組，其中 `cs[i].0` 是送端、`cs[i].1` 是接收端。固定次數的 `spawn` 迴圈因而會建立固定數目的任務實例及內部通道。

合成器在展開頂層 task 時會執行其網路建立部分，取得完整的 spawn tree，再為每個 spawn 建立任務實例、為每條內部通道建立 FIFO。只有在執行期才能決定 spawn 次數的網路不受支援。

## 10. 標準庫 `std`

目前標準庫提供下列兩種參數化 task 產生器。兩者都是一般 Fluxa task 網路，而非黑盒 IP。

### 10.1 `std::SystolicMatmul::<N, AW, CW>(a, b, c)`

介面如下：

- `a`：`in chan<int<-(1 << (AW - 1)) ..= (1 << (AW - 1)) - 1>>`，即 `AW` 位元有號整數。
- `b`：與 `a` 相同。
- `c`：`out chan<int<-(1 << (CW - 1)) ..= (1 << (CW - 1)) - 1>>`，即 `CW` 位元有號整數。

其契約為：

1. `A`、`B` 都是 $N \times N$ 的 row-major 矩陣。
2. `a` 與 `b` 以 lockstep 方式讀取；每一輪配對一個 `a` 值與一個 `b` 值，一組矩陣共讀取 $N^2$ 對。
3. 輸出為 $C = A \times B$，順序為 row-major。
4. 上述工作持續重複，直到 `a` 關閉；此時 `b` 亦須關閉，產生器關閉 `c`。
5. 每個輸出元素是 $N$ 個乘積之和。呼叫端必須使 `CW` 足以容納總和；產生器不檢查累加溢位，累加採回繞語意。

其結構為 output-stationary 的 $N \times N$ 個 PE；`A` 往東傳播、`B` 往南傳播，內部通道深度為 2。

```rust
task Mm4(a: in chan<i8>, b: in chan<i8>, c: out chan<i32>) {
    spawn std::SystolicMatmul::<4, 8, 32>(a, b, c);
}
```

### 10.2 `std::Window3x3::<W, H, PW>(x, w)`

介面如下：

- `x`：`in chan<uPW>`，其中 `uPW` 表示 `PW` 位元無號整數。
- `w`：`out chan<[[uPW; 3]; 3]>`。

其契約為：

1. `x` 接收寬 `W`、高 `H` 的 row-major frame。
2. 對每個內部像素 $(r,c)$，其中 $1 \le r \le H-2$、$1 \le c \le W-2$，依 row-major 順序輸出一個 $3 \times 3$ 視窗。
3. 視窗元素滿足 $w[i][j] = x[r-1+i][c-1+j]$，其中 $0 \le i,j < 3$。
4. frame 可持續重複，直到 `x` 關閉。

實作使用兩條各含 `W` 個像素的 line buffer，以及一個 $3 \times 3$ 滑動視窗。

## 11. 測試與三種執行方式

`test` 項目包含測試程式本體。測試可建立通道、spawn task、傳送資料，並以 `assert cond` 或 `assert cond, "msg"` 檢查結果。

同一份 Fluxa 程式可依下列三種方式執行：

| 命令 | 執行方式 |
| --- | --- |
| `reda sim file.fx ...` | 由行為直譯器執行 `test`。 |
| `reda emu file.fx ...` | 先編譯成狀態式執行器，再執行同一組 `test`。 |
| `reda gatesim opt\|ice40\|ecp5\|asic\|sky130 file.fx ...` | 合成 task，將其換成通用閘或目標元件網表，再執行同一組 `test`。 |

例如：

```sh
reda sim fluxa/examples/fir4.fx
reda emu fluxa/examples/fir4.fx
reda gatesim opt fluxa/examples/fir4.fx
```

直譯器、編譯模擬器及 gatesim 必須對每個 test 給出相同結果，包括斷言成功或失敗，以及各通道的 token 序列。gatesim 使用目標元件網表時，其行為結果仍須與行為直譯器一致；不一致視為實作錯誤。

## 12. 合成子集與硬體介面

### 12.1 外部硬體介面

合成頂層的通道參數 `c` 會展開為四組埠：

| 埠 | 語義 |
| --- | --- |
| `c_data` | token 資料。 |
| `c_valid` | 來源端表示有 token 可傳送。 |
| `c_ready` | 接收端表示可接受 token。 |
| `c_close` | 表示此 token 是通道結束訊號。 |

token 只在 `c_valid && c_ready` 時移動。`c_close = 1` 的 token 表示通道結束；其 `c_data` 內容不承載資料。

非通道的標量參數默認成為輸入埠；使用 `--param NAME=VALUE` 固定後，該參數成為常數，不再形成外部埠。內部建立的通道則成為深度等於 `depth` 的 FIFO；小型 FIFO 由暫存器實作，大型 FIFO 可改用 block RAM。

自 v1.1 起，同一個硬體介面也可以用 `reda synth --rtl` 印成 SystemVerilog：一個模組、一個 block 一個狀態、通道即 valid/ready 埠。該輸出與網表來自同一份降階與同一套值域規則，因此兩者對埠、寬度與握手的描述一致；它供人閱讀與交接，不取代網表作為合成輸入（手冊 7.13、9.10）。

### 12.2 迴圈排程、記憶體與暫存器

`pipeline(ii = n)` 使用模數排程目標。合成器須確認一個迭代內的通道操作及記憶體存取能放入指定的時隙；無法達成時報告 `E0412`，並指出造成瓶頸的通道操作、埠或資源。`ii = 1` 必須能以每個時脈一個迭代達成；目前後端對 `ii >= 2` 的迴圈退回一般 FSM，因此仍保留語義，但不表示該迭代只需 `n` 個時脈。

`mem<T, N>` 若只以 `m[i]` 形式讀寫，可映射為 block RAM。`@reg` 則映射為暫存器，並遵守第 3 節的迭代提交語意：同一迭代內讀到的是迭代開始時的值，寫入在迭代結束時提交。

### 12.3 不受 synthesis 支援的構造

| 構造 | 合成結果 |
| --- | --- |
| 遞迴 | 明確報錯，不產生網表。 |
| 執行期才決定 spawn 次數 | 明確報錯；spawn tree 必須可靜態展開。 |
| 浮點數 | 明確報錯。 |
| `stage` 層 | 明確報錯。 |
| Type generic 參數 | 明確報錯；硬體元素型別須使用 const generic。 |
| 通道陣列參數，如 `outs: [chan<T>; N]` | 僅模擬支援，不合成。 |
| `print` | 呼叫被丟棄，不產生硬體邏輯。 |

### 12.4 任務網路報告

靜態 spawn tree 會合成為一個網路：每個 spawn 對應一個任務實例，每條內部通道對應一個 FIFO。報告會列出各任務實例及 FIFO 的閘數。

使用 `--format json` 時，報告包含 `metrics.gates_by_part`，可用來比較任務實例與 FIFO 的面積。若 FIFO 的閘數占總閘數至少 30%，合成器另發出警告，提示內部 FIFO 面積過大。

## 13. 診斷

### 13.1 診斷代碼

| 代碼 | 狀態 | 意義與偵測位置 |
| --- | --- | --- |
| `E0102` | 已實作 | 除數的型別範圍包含 0。`reda check` 可在靜態時發現；模擬器執行到此除法時回報 `division by zero`。 |
| `E0301` | 已實作 | 值無法放入落點型別，或 carry／累加值溢位。模擬器執行時報告 `E0301`；`reda check` 以區間分析靜態報告，並列出可容納該值的最小型別。 |
| `E0401` | 已實作 | `pipeline` 迴圈的一輪使用超過可用埠數。`reda check` 以單一 bank 模型檢查；通道每時脈最多傳送一個 token，記憶體有一個讀埠及一個寫埠。 |
| `E0412` | 已實作 | `pipeline(ii = n)` 無法達成要求的排程。由 synthesis 報告，並列出瓶頸及可行的 II 或結構修正。 |
| `E0501` | 已實作 | 同一通道的送收 token 數不守恆，且差額會使執行阻塞。由 `reda check` 報告。 |
| `W0503` | 暫定 | 通道尚有剩餘 token，且差額可放入 FIFO；不必然死結，但仍有 token 未被接收。由 `reda check` 報告。 |
| `E0701` | 暫定 | 執行期死結。當所有存活 task 均阻塞時，由模擬器報告，並列出每個 task 正在等待的通道或操作。 |
| `E0702` | 暫定 | 端點所有權違規。端點交給 `spawn` 後仍被使用；模擬器報告 `task does not own the rx endpoint`，`reda check` 亦可靜態發現。 |
| `E0703` | 暫定 | 索引越界。模擬器在執行時發現；`reda check` 可依索引區間作靜態判定。 |

### 13.2 診斷原則與 JSON 格式

每則診斷均須包含：

1. **位置**：發生問題的檔案及行號。
2. **證據**：具體數值、值域、通道差額、資源使用量或其他可驗證依據。
3. **可行修正**：足以讓程式重新通過型別或資源檢查的修改方向。

`--format json` 使用 `rueda/1` schema。每個 diagnostic 至少包含：

| 欄位 | 內容 |
| --- | --- |
| `code` | 診斷代碼。 |
| `file` | 來源檔案。 |
| `line` | 來源行號。 |
| `data` | 支援判斷的結構化資料，例如值域、最小型別、累加量或資源使用量。 |
| `notes` | 證據說明及修正建議。 |

## 14. 保留（未實作）

下列項目源自 v0.1 的設計或後續規劃，目前均不得視為 Fluxa v1.0 的已實作功能。

| 項目 | 目前狀態 |
| --- | --- |
| `stage` 層與 `E0230` | 不受支援；解析 `stage` 時回報 `not supported`。尚無值有效區間或跨時脈週期檢查。 |
| 非確定的通道操作 | `rx.try_recv()`、`rx.empty()`、`rx.len()` 只允許在 `stage` 層；task 層使用是錯誤（§7.2）。 |
| `E0210`（`comb fn` delay） | 不檢查組合路徑是否超過時脈週期。 |
| `iface` 與 `schedule` | 解析後忽略，不產生介面握手或排程語意。 |
| Graph API | 不提供 v0.1 第 5.2 節的 `Graph` 型別、`g.add`、`g.connect` 等操作，也不提供 `E0603` 的未連接或重複連接檢查。靜態 spawn tree 並不取代 Graph API。 |
| Bank 分割 | `@bram(cyclic = B, ports = ...)` 的 placement 引數會被略過；目前只有單一 bank 模型，不實作 v0.1 第 3.5 節的 cyclic／block bank 規則。 |
| `E0601` | 尚無 comptime 步數上限及相應診斷。 |
| `W0502` | 尚不計算 SDF 最小 FIFO 深度，亦不發出因 FIFO 深度不足而降低吞吐的警告。 |
| `assume` | 不支援 `assume` 斷言或以假定條件強化區間分析。 |
| Compile-time function parameters | 不支援將函式或 task 作為值傳遞；例如 `map(f)` 的函式值形式及跨任務網路的平行樣式尚未實作。`map(\|x\| ...)` 的 lambda 形式仍依第 8 節支援。 |
| v0.1 第 7 節的其他標準庫模組 | `std::num`、`std::stream`、`std::mem`、`std::axi`、`std::dsp`、`std::test` 等規劃中的模組化 API 尚未提供。已實作者僅限第 8 節列出的全域內建，以及第 10 節的 `std::SystolicMatmul` 與 `std::Window3x3`。 |
