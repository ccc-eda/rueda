# 12.6 防止幻覺與版本漂移

## 12.6.1 幻覺在硬體中的代價

在一般文字生成中，幻覺可能只是一句錯話；在硬體中，幻覺可能是：

- 一個不存在的 API；
- 一個尚未實作的語言功能；
- 一個看起來合理但錯誤的位寬公式；
- 一個不存在的命令參數。

這些錯誤若進入程式，可能在編譯或檢查時被發現，也可能一路潛伏到合成或上板才暴露。因此，防幻覺不是禮貌問題，而是工程安全問題。

## 12.6.2 要求引用來源

prompt 應要求 agent 引用：

- 語言規格章節；
- 實際程式行號；
- 命令與輸出；
- 標準庫文件。

沒有來源的主張，應該被視為待驗證，而不是事實。

## 12.6.3 最小可重現案例

當 agent 聲稱某個功能可用或某個 bug 存在時，要求它提供最小可重現案例：

```sh
reda check tiny.fx
```

這個案例應該短到可以人工閱讀，且能重現問題。沒有最小案例的宣稱，通常難以驗證。

## 12.6.4 版本漂移

工具與語言會更新，文件與程式可能不同步。防漂移的方法：

- 在專案中記錄使用的版本；
- 讓 CI 固定工具版本；
- 用測試鎖住關鍵行為；
- 定期重新執行文件中的命令。

若 agent 讀到舊文件而引用已移除的功能，版本紀錄可以幫助你快速發現。

## 12.6.5 不確定時就提問

prompt 應明確規定：遇到規格缺口、版本不明或命令不存在時，先提問，不要自行補完。這條規則看似簡單，卻能阻止很大一部分幻覺。

## 12.6.6 人工抽查

最後，人工抽查仍然是必要的。抽查的重點不是逐行閱讀，而是：

- 這個主張有來源嗎？
- 這個數字是怎麼算出來的？
- 這個命令真的存在嗎？
- 這個測試真的測到契約嗎？

把抽查集中在高風險主張上，比平均閱讀更有效。
