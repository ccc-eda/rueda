# 5.13 可重現 oracle 的設計原則

把本章方法濃縮成六條原則：

### 原則一：oracle 跟著契約成長

每增加一條契約，例如「輸出必須與輸入一一對應」，就增加相應證據：值、順序、數量或關閉。不要等 bug 出現才想該斷言什麼。

### 原則二：觀察資料放進通道

正式 oracle 應透過 token 傳遞。`print` 適合診斷，不適合跨 task 的精確比較。

### 原則三：先比較通道投影，再比較全域事件

全域 trace 可能合法交錯；每條通道的有序序列才是穩定的語意單位。

### 原則四：測試是隔離的世界

每個測試重新建立通道與元件，避免順序依賴，也讓單一案例能獨立重現。

### 原則五：兩種排程器使用同一份測試向量

不要為原生與合作式排程各寫一份「差不多」的測試；兩者必須執行完全相同的案例與斷言。

### 原則六：失敗要留下位置、證據與修正方向

一個好的失敗證據至少回答：在哪裡失敗、實際看到什麼、預期什麼。`--trace` 與 `--stats` 提供行為證據；下一章的靜態診斷則會進一步把錯誤提前。
