# 9.7 時脈、重置與約束

## 9.7.1 頂層的隱含訊號

合成後的硬體通常需要兩個全域訊號：

- `clk`：時脈；
- `rst`：重置。

在 FPGA 流程中，這兩個訊號必須被約束到實際接腳，並連到所有需要時脈與重置的暫存器。若某個 FIFO 或 FSM 沒有正確接到重置，模擬可能通過，但上電後狀態不確定。

Fluxa 的語言層不需要你手寫時脈樹；但設計者仍要清楚：

- 哪些狀態在重置後必須是已知值？
- 通道埠在重置期間應該呈現什麼 `valid/ready`？
- 外部來源在重置解除前是否可能送 token？

## 9.7.2 時序約束的意義

約束檔（`pcf`、`lpf` 或 ASIC 的 SDC）告訴工具：

- 時脈頻率是多少；
- 哪些腳位連到哪些訊號；
- 外部輸入與輸出的延遲假設；
- 是否有非同步介面或假路徑。

沒有約束，工具可能會用過度樂觀的假設做時序分析。對 `valid/ready` 串流介面而言，尤其要明確外部資料的到達時間與接收端的準備時間。

## 9.7.3 尚未建模的項目要誠實說明

Fluxa v1.0 尚未提供完整的週期精確 `stage` 層，也沒有所有形式的組合延遲檢查。這表示：

- `pipeline(ii = 1)` 是排程要求，不是時序保證；
- 某些組合路徑的實際延遲要靠後端報告與量測；
- 跨時脈域的行為需要設計者自行處理，不能假設語言會自動插入同步器。

把「尚未實作」寫進設計文件，不是缺點，而是可驗證工程的一部分。讀者與審核者才知道哪些結論有工具支持、哪些是待驗證的假設。

## 9.7.4 重置與通道關閉

通道關閉（`close`）與重置是兩種不同的概念：

- 重置讓硬體回到已知初始狀態；
- 關閉表示某條串流不會再有新 token。

在硬體介面上，`close` 是一個 token，會通過 `valid/ready` 握手；重置則是全域事件。若把兩者混為一談，可能出現「重置後通道仍被視為關閉」或「關閉訊號被重置吃掉」的錯誤。

設計時應明確定義：

- 重置期間 `close` 埠的行為；
- 重置解除後第一筆 token 的順序；
- 若來源提前關閉，接收端如何結束。

## 9.7.5 一份可交付的約束摘要

至少應記錄：

| 項目 | 內容 |
| --- | --- |
| 時脈 | 頻率、來源、接腳 |
| 重置 | 極性、同步或非同步、接腳 |
| 串流埠 | data/valid/ready/close 的接腳 |
| 外部延遲 | 輸入與輸出假設 |
| 例外 | 假路徑、非同步介面 |

這份摘要與第 9.9 節的交付摘要合併後，就是別人重現你的硬體所需的全部資訊。
