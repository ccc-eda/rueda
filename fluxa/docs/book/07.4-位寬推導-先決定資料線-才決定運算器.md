# 7.4 位寬推導：先決定資料線，才決定運算器

硬體前端不能等到產生網表時才問「這個 `int` 到底要幾位元？」。型別與值域分析必須在控制流降階前後提供一致答案。

Fluxa 的整數模型不是「某個平台預設的 32 位元」。例如 `i8` 精確表示 `-128..=127`，`u8` 表示 `0..=255`。運算子先依來源值域求出結果值域，再把該值域轉成最小容納寬度。對第 3 章的 FIR 而言：

- 8 位元樣本乘 8 位元係數，結果需要足夠容納兩個 8 位元數乘積的寬度；
- 多個乘積相加，範圍會再次擴大；
- 最後轉回 `i8` 時，才依明確策略選擇捨入與飽和。

因此「乘加器要 16 位元還是多少位」不是工具任意挑選的結果。若來源值域是 `-128..=127`，兩者相乘的完整值域是 `-16256..=16384`；這個結果至少需要 16 個二補數位元。四個乘積再相加，就必須重新推導，不能沿用其中一個乘積的寬度。

### 7.4.1 邏輯值域與實體儲存寬度

有一個容易混淆的地方：語意值域不一定要等於實體型別的完整二補數範圍。

```fluxa
let count: u4 = 0;
```

`count` 的語意值域是 `0..=15`，恰好需要 4 位元；但若某段計算暫時得到 `0..=20`，即使最後又證明它永遠會降回 `0..=15`，工具仍不能在未證明前任意截位。Fluxa 的做法是先用足以容納 `0..=20` 的寬度保存，之後若有明確轉換，才依 `wrap` 或 `sat` 回到 `u4`。

這也解釋了為何固定點轉換需要三種資訊：

```fluxa
acc.to::<i16>(round = nearest, ovf = sat)
```

- `round = nearest` 決定被捨去的低位如何影響結果；
- `ovf = sat` 決定超出 `i16` 時夾在上下界；
- 目標型別 `i16` 決定資料線與暫存器寬度。

在網表裡，捨入與飽和都不是額外的「軟體步驟」，而是定點運算器、多工器與比較器組成的組合邏輯。

### 7.4.2 未標型別變數的固定點推導

有些值可以從初始值推導型別，但後續賦值可能讓值域擴大。硬體生成器因此可能反覆執行：

1. 以目前已知的型別建立資料路徑；
2. 執行區間分析，發現新值域；
3. 若新值域需要更寬的暫存器或運算器，就擴寬；
4. 重新建立受影響的路徑。

這是一個固定點問題，不應靠「先猜 32 位元」解決。若反覆擴張仍無法穩定，工具會要求設計者明確宣告型別，而不是永遠保留一個過大的暫存器。對硬體設計而言，明確型別也讓審查者知道：多出來的位元究竟來自演算法需求，還是工具不知道真正的值域。

### 7.4.3 常數摺疊

常數運算若在編譯期可求值，就不應在硬體中保留完整運算器。例如：

```fluxa
const SHIFT: u5 = 4;
const SCALE: i16 = 3;
```

`SHIFT` 最後通常只是一組接線；`SCALE` 可能是常數乘法的特殊化結果。常數摺疊不只省閘，也能讓控制條件簡化。例如 `if N == 4` 在 `N` 已固定後，不是每次執行都比較，而是直接連到代表真值的常數網。

但不是所有「看起來像常數」的表達式都應摺疊。例如參數由 `--param` 固定時，它是這個實例的硬體常數；沒有固定的非通道參數則成為頂層輸入埠。第 9 章會詳細說明這兩種情況。
