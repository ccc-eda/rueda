# 5.7 用 `--stats` 檢查數量與容量

`--stats` 為每條有活動的通道列出：

```text
  channel                        depth     sent     recv   max-occ
  test:tx->rx                        8        6        6         1
  test:ty->ry                        8        6        6         1
```

各欄位的意義如下：

| 欄位 | 意義 | 適合驗證什麼 |
| --- | --- | --- |
| `depth` | FIFO 容量 | 測試使用的契約容量 |
| `sent` | 成功送入 FIFO 的 token 數 | 產生端是否少送或多送 |
| `recv` | 成功取出的 token 數 | 消費端是否取完 |
| `max-occ` | FIFO 曾經達到的最大佔用 | 背壓與容量是否接近上限 |

`--stats` 對除錯特別有用：

- `sent` 比預期少：來源可能尚未送完，或網路在途中失敗；
- `sent` 比預期多：來源可能多產生 token；
- `recv` 少於 `sent`：仍有 token 留在 FIFO，或消費端提前停止；
- `recv` 等於 `sent` 但輸出值錯誤：數量守恆，內容或順序錯誤；
- `max-occ` 接近 `depth`：來源與消費端速率差異大，網路經常處在背壓邊緣。

但 `max-occ` **不是排程無關的正值**。即使 token 序列固定，不同排程也可能讓來源先填滿 FIFO，或讓消費端立刻取走。因此 `sent` 與 `recv` 是較適合跨排程比較的數量證據；`max-occ` 則是診斷與容量資料。

若測試在讀完所有輸出後就結束，尚未消費的 token 仍可能留在 FIFO。stats 中的 `sent != recv` 正好可以提醒測試作者：還有東西沒有被觀察。
