# 11.2 案例一：4 階 FIR

## 11.2.1 規格

輸入是一串 8 位元有號樣本，係數固定為四個常數。輸出是卷積：

$$
y[n] = \sum_{k=0}^{3} c_k\,x[n-k]
$$

契約：

- 每個輸入 token 對應一個輸出 token；
- 同一通道內維持順序；
- 輸入關閉後，輸出在處理完剩餘樣本後關閉；
- 邊界與溢位策略必須明確。

## 11.2.2 介面與型別

```fluxa
const COEF: [i8; 4] = [1, 2, 3, 4];

task Fir(input: chan<i8> in, out: chan<i16> out) {
    // 4 階 FIR
}
```

四個 8×8 乘積最大需要 16 位元，四項相加需要 18 位元。若輸出介面是 `i16`，必須選擇飽和或回繞：

```fluxa
out.send(sum.sat::<i16>());
```

這個選擇不是細節，而是契約的一部分：飽和會把過大值夾住，回繞會保留低位元。兩者在邊界案例上的輸出完全不同。

## 11.2.3 歷史樣本

用 `@reg` 保存四個歷史樣本：

```fluxa
let mut h0: i8 @reg = 0;
let mut h1: i8 @reg = 0;
let mut h2: i8 @reg = 0;
let mut h3: i8 @reg = 0;

for s in input {
    h3 = h2;
    h2 = h1;
    h1 = h0;
    h0 = s;
    let y = COEF[0] * h0 + COEF[1] * h1 + COEF[2] * h2 + COEF[3] * h3;
    out.send(y.sat::<i16>());
}
out.close();
```

`@reg` 保證同一輪讀到的是迭代開始時的舊值，因此四個賦值不會互相覆蓋。

## 11.2.4 排程

若要求每拍一個樣本，可加上 `pipeline(ii = 1)`，並用 `.tree_sum()` 把乘積組成平衡加法樹：

```fluxa
pipeline(ii = 1) for s in input {
    h3 = h2; h2 = h1; h1 = h0; h0 = s;
    let y = (0..4).unrolled()
                    .map(|k| COEF[k] * win(k))
                    .tree_sum();
    out.send(y.sat::<i16>());
}
```

注意：`pipeline` 是排程要求，不代表時序一定通過。第 8 章已說明，資料路徑深度與後端時序仍需量測。

## 11.2.5 測試

至少測：

- 正常序列；
- 最大正數與最小負數；
- 全零；
- 單一樣本；
- 關閉後的輸出數量。

測試應比對完整輸出序列，而不是只比對總和或最後一個值。
