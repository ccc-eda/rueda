# 7.1 學習目標

前四章建立了 Fluxa 的行為語意：值有封閉值域，task 是程序網路中的程序，通道是有界 FIFO，而 token 的順序、數量與關閉語意不能依賴排程。第五章再用行為模擬建立正確性的 oracle，第六章讓值域、端點所有權與資源問題在合成前就暴露。

現在要跨過最關鍵的一道牆：**一段描述「做什麼」的 Fluxa 程式，究竟怎麼變成一組真的會隨時脈運作的電路？**

答案不是把每一行程式逐字翻成 Verilog。Fluxa 會先把程式拆成兩種東西：

- **控制**：現在處於哪個狀態？接下來要接收、計算、傳送，還是等待？
- **資料**：在目前狀態下，運算元是哪些值？加法器、比較器與多工器應計算什麼？

前者形成有限狀態機（Finite State Machine, FSM），後者形成資料路徑（datapath）。兩者透過暫存器相連：狀態暫存器記住「正在做哪一步」，資料暫存器則保存跨步驟仍然需要的值。

本章以 Fluxa 語言規格 v1.0（2026-11-21）與 `rueda 0.7.0` 為基準。我們會從 `.fx` 原始碼一路追到通用閘網表，並以 4 階 FIR 說明：一次 `recv`、一組乘法與加法、一次 `send`，如何分別變成狀態邊界、資料路徑與握手邏輯。

完成本章後，你應該能夠：

1. 說明解析、常數求值、靜態展開、位寬推導、CFG／FSM 降階與網表生成各自負責什麼。
2. 解釋為何 `recv`、`send` 與 `close` 必須形成狀態邊界，而一般算術可以留在同一狀態的組合資料路徑。
3. 把 `if`、`match`、`return` 與迴圈映射到狀態轉移、比較器、多工器與暫存器。
4. 分辨 FSM 狀態暫存器、task 變數暫存器、FIFO 儲存空間，以及只在單一狀態內存在的組合值。
5. 說明靜態 `spawn` 網路如何展開成多個 task 實例，並以內部 FIFO 連成單一網表。
6. 閱讀網表報告中的 task 實例、FIFO 與閘數，並知道為何通用閘數不能直接當成 FPGA LUT 數或時序結果。

> **版本界線**：本章描述的是已實作的基本 FSM 降階。`pipeline`、`unroll`、`serial` 只先說明它們解決的排程歧義，資源與 initiation interval（II）留到第 8 章；外部通道如何映射成 `valid/ready/close` 埠則留到第 9 章。尚未實作的 `stage` 層、Graph API 與完整 SDF 分析，不會被當成現有保證。
