# 5.8 可重現測試的工作流

可重現不是指每次失敗都得到一模一樣的畫面，而是指任何人都能用相同來源、相同命令與相同證據重現判斷。

### 5.8.1 先固定最小重現命令

先列出測試，再只執行它：

```sh
reda sim --list fluxa/examples/fir4.fx
reda sim --test fir4_step fluxa/examples/fir4.fx
```

若失敗，再加入觀察選項：

```sh
reda sim --test fir4_step --trace --stats fluxa/examples/fir4.fx
```

若要確認排程無關性：

```sh
reda sim --test fir4_step --trace --stats fluxa/examples/fir4.fx
reda sim --coop --test fir4_step --trace --stats fluxa/examples/fir4.fx
```

使用 `--test` 可以避免其他測試的輸出混入診斷，也讓失敗範圍立刻縮小。

### 5.8.2 把失敗轉成四類問題

看到 assertion failed 後，先判斷它屬於哪一類：

| 症狀 | 優先懷疑 |
| --- | --- |
| 第一個值就錯 | 演算法、係數、型別或初始狀態 |
| 前幾個值對，後面才錯 | 歷史狀態、索引或迭代提交 |
| 值都對但次序不對 | 通道串接、緩衝區順序或競爭式消費 |
| 值與數量都對但測試不結束 | 關閉責任或等待環 |
| 原生通過、合作式失敗 | 非確定通道操作、共享狀態或錯誤的排程假設 |

這種分類能把「隨便改一行」變成可追查的除錯過程。

### 5.8.3 比較排程器時比較語意投影

完整流程可以把每次執行保存成證據：

```sh
reda sim --trace --stats fluxa/examples/pipeline.fx > native.log 2>&1
reda sim --coop --trace --stats fluxa/examples/pipeline.fx > coop.log 2>&1
```

不建議直接以 `diff native.log coop.log` 作為唯一判定，因為獨立通道的 trace 交錯和 `max-occ` 可能不同。應比較：

1. 每個測試的斷言結果；
2. 每條通道的有序 token 投影；
3. `sent`、`recv` 數量；
4. 關閉是否發生，以及每條通道關閉前送出的 token 數；
5. 若規格明定跨通道關係，再針對那個關係建立額外斷言或同步。

這種比較方式不是放寬驗收，而是把 oracle 對準真正的語意。

### 5.8.4 證據應可被保存與審核

一份可交付的行為證據至少包含：

- Fluxa 原始碼版本或 commit；
- 工具版本；
- 完整命令與選項；
- 測試向量與期望序列；
- 斷言結果；
- 必要時的 trace 與 stats。

若由 CI 執行，還應保存非零退出碼，而不只是保存最後一行 log。`reda sim` 遇到測試失敗會以非零狀態結束，這讓自動化流程能可靠區分「通過」與「只是印出錯誤文字」。
