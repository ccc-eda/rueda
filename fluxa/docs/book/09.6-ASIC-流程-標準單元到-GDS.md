# 9.6 ASIC 流程：標準單元到 GDS

## 9.6.1 從可程式邏輯到固定電路

FPGA 把邏輯放在預先做好的可配置資源裡；ASIC 則把邏輯固定成標準單元（standard cell），再經過擺置、繞線與驗證，最後產生 GDSII 佈局。

`reda asic` 支援兩種流程：

```sh
reda asic --pdk vlib --verilog fir.v fir.fx
reda asic --pdk sky130 --gds fir.gds --def fir.def fir.fx
```

- `vlib` 是內建的教育用標準單元庫，適合快速理解流程。
- `sky130` 使用 SkyWater SKY130 `sky130_fd_sc_hd`，可產生真正的 GDSII。

## 9.6.2 ASIC 流程的主要階段

| 階段 | 作用 |
| --- | --- |
| 技術映射 | 把通用網表換成目標 PDK 的標準單元 |
| 擺置（placement） | 決定每個單元在晶粒上的位置 |
| 時脈樹（CTS） | 建立時脈分布網路，控制時脈偏移 |
| 繞線（routing） | 連接所有單元與腳位 |
| 時序分析 | 檢查建立時間與保持時間 |
| 功耗分析 | 估算動態與靜態功耗 |
| DRC／LVS | 檢查設計規則與佈局對電路的一致性 |
| 產出 GDSII | 交付給晶圓廠的佈局檔 |

FPGA 流程也有映射、擺置與繞線，但 ASIC 多了對實體規則、時序角落、功耗與良率的嚴格要求。這些不是「多幾個檢查」而已，而是會直接影響晶片是否能製造。

## 9.6.3 為什麼 ASIC 的時序更難

FPGA 的時脈網路與資源位置是预先設計好的；ASIC 的時脈樹與繞線必須由工具建立，且會受到擺置與擁塞影響。因此，同一個網表在 FPGA 上可能輕鬆跑到某個頻率，在 ASIC 上卻需要更多管線與時脈樹調整。

此外，ASIC 要考慮：

- 製程變異與溫度、電壓角落；
- 建立時間與保持時間同時滿足；
- 繞線電容與串擾；
- 功耗密度與散熱；
- DRC 與 LVS 的實體正確性。

這也回到第 8 章的原則：排程屬性只是要求，真正的時序與面積必須由後端報告證明。

## 9.6.4 從報告回推設計

ASIC 報告中的資源與時序數字，應該被當成設計決策的證據：

- 若關鍵路徑總在乘法器，考慮共享或改成加法／移位實作。
- 若面積被正反器主導，檢查 `@reg` 與 FIFO 是否過多。
- 若時脈樹功耗過高，考慮降低時脈域數量或使用時脈閘控。
- 若 DRC 失敗，先確認是工具設定、PDK 版本，還是佈局密度問題。

## 9.6.5 ASIC 與 FPGA 的共同紀律

無論走哪一條後端，工程紀律相同：

1. 先有正確的行為模型與測試。
2. 再通過靜態檢查。
3. 合成後讀報告，而不是只看「成功」。
4. 用閘級模擬確認網表行為。
5. 保存命令、版本與產物，讓結果可重現。

ASIC 不會讓錯誤的語意變正確，只會讓錯誤更貴。這也是為什麼本書把型別、通道與驗證放在後端之前。
