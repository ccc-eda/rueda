# 1.5 三種時間：行為、合成、外部世界

硬體設計最容易被誤解的地方，是把不同層次的「時間」當成同一件事。至少要分開三種時間。

### 1.5.1 行為時間：token 的邏輯順序

在行為模擬中，最重要的是 token 的因果與順序：哪個 token 先被產生，哪個輸入對應哪個輸出，通道何時關閉。這個時間軸通常以事件或步驟表示，不必等於真實晶片的一個時脈週期。

例如，FIR 的行為模型可以記錄：

```text
recv x[0]
recv x[1]
recv x[2]
recv x[3]
send y[0]
send y[1]
send y[2]
send y[3]
close output
```

這串紀錄是正確性 oracle 的基礎。它讓我們不只檢查「最後的數字對不對」，還能檢查「有沒有少一個 token、順序是否反轉、輸出是否提前關閉」。

### 1.5.2 合成時間：FSM 狀態與時脈

合成後，行為程序會被拆成有限狀態機（FSM）、資料路徑、暫存器與記憶體。FSM 的狀態轉移一個時脈一格，資料路徑在時脈邊界捕捉結果。此時「延遲 4 拍」「II = 1」等描述才開始具有直接的硬體意義。

同一份 token 行為可以在不同排程下被實現。例如，完全展開的 FIR 可能用 1 拍完成資料路徑，序列 MAC 可能用 4 拍；兩者的 token 順序與數值可以相同，但實體時間和資源不同。

### 1.5.3 外部時間：裝置間的傳輸時間

最後是晶片與晶片、晶片與記憶體或晶片與感測器之間的時間。外部介面可能有自己的時脈、握手、協定與延遲；一個元件在內部算完，不代表外部馬上能收到結果。

因此，設計文件不應只寫「每拍一個」。較完整的說法是：

> 邏輯上，元件保持輸入與輸出的 token 對應；目標硬體排程為 II = 1，內部延遲不超過 L 拍；外部介面以某種 valid/ready 協定交換資料，傳送端在接收端未表示 ready 時保持資料與 valid。

這個說法把行為承諾和物理條件連起來，卻沒有混為一談。

| 問題 | 行為時間 | 合成時間 | 外部時間 |
| --- | --- | --- | --- |
| 主要觀察 | token 順序、數量、對應、關閉 | 狀態轉移、延遲、II、管線 | 握手、傳輸延遲、協定錯誤 |
| 常用工具 | `reda sim` | `reda emu`、synthesis 報告 | FPGA/ASIC 介面與時序報告 |
| 常見失敗 | 少 token、順序錯、關閉錯誤 | 吞吐不符、資源超標、路徑太慢 | valid/ready 違例、跨時脈域問題 |

三種時間必須保持**可驗證的對應關係**，但不能直接畫上等號。行為模擬給的是因果，合成報告給的是實體排程，外部測試給的是系統整合結果。
