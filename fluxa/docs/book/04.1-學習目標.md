# 4.1 學習目標

前兩章先建立兩項基礎：Fluxa 的 `task` 能在程式中啟動獨立程序，而範圍型別會替每個值找出可安全容納它的位寬。本章要把這兩項基礎接起來，問一個比「這段程式怎麼執行？」更接近硬體設計的問題：

> 哪些程序可以同時存在？它們透過什麼交換資料？資料是第幾個抵達？誰能關閉資料流？當某個程序跑得比另一個快時，系統如何維持正確，而不是讓某個值被漏掉？

這正是 **Kahn 程序網路（Kahn process network, KPN）**要回答的問題。

在 Fluxa 中，`task` 是程序網路的節點，通道是節點之間的有界 FIFO，token 則是沿著 FIFO 流動的資料。我們會先從一段普通的 FIR 濾波器開始，把它拆成「來源、FIR、消費者」，再逐步處理通道方向、元素型別、端點所有權、廣播、背壓與死結。最後，你會得到一張不只「看起來能跑」，而且能逐條驗證的 FIR 任務網路契約。

完成本章後，你應該能夠：

1. 說明 `task`、token、通道與 FIFO 在 Kahn 程序網路中各自扮演什麼角色。
2. 正確建立通道，使用 `send`、`recv`、`close` 與 `for v in rx`，並理解阻塞的發生時機。
3. 讀懂任務介面上的 `in chan<T>`、`out chan<T>`，分清方向錯誤、元素型別錯誤與值域不相容。
4. 說明端點為何是線性資源，以及 `spawn` 與 `broadcast` 何時會移轉或消耗端點所有權。
5. 使用 `spawn`、`parallel` 與 `broadcast` 建立固定形狀、可組合的程序網路。
6. 從 FIFO 深度與等待關係推論背壓，辨認暫時等待、永久等待與死結。
7. 將 FIR 組成「來源 → FIR → 消费者」網路，並為每條通道寫出元素型別、順序、深度與關閉責任。

> **版本界線**：本章以 Fluxa 語言規格 v1.0（2026-11-21）與 `rueda 0.7.0` 為準。`stage` 層、`try_recv`、`empty`、`len` 與 Graph API 尚未實作；本章只使用 task 層已提供的阻塞式通道操作。
