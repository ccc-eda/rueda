# 9.10 用 RTL 接入既有流程

第 7 章說明了 RTL 視圖長什麼樣；本章說明它怎麼**用**。一句話：網表讓工具接手，RTL 讓人看懂，而兩者必須是同一件事的兩種印法。

### 9.10.1 三種輸出，各有用途

| 產物 | 指令 | 給誰 | 用途 |
| --- | --- | --- | --- |
| 行為模擬 | `reda sim` | 設計者 | 確認語意 |
| 閘級網表 | `reda synth --top T` | 工具 | 佈局佈線、時序分析 |
| 可讀 RTL | `reda synth --rtl out.sv --top T` | 人（與交接對象） | 檢查、交接、驗證 |

三者來自同一個前端與同一套降階，所以「模擬器說對」與「網表是對的」之間不再有空隙；而 RTL 讓你**讀得出**那個對不起來的地方。

### 9.10.2 一個最小的交接流程

假設要把一個 FIR 交給別的團隊做 FPGA：

```sh
# 1. 產出 RTL
reda synth --rtl fir.sv --top Fir examples/fir.fx

# 2. 產出網表（給自己的流程）
reda synth --top Fir examples/fir.fx --format json > fir.json
```

`fir.sv` 裡有：一個 `Fir` module、網路需要的 FIFO module、以及每個實例的 module。對方拿著 `fir.sv` 可以：

- 直接丟進他們的模擬器或合成器（若接受 SystemVerilog）；
- 逐行閱讀、標註、掛到 issue 上；
- 與自己的 RTL coding 風格對齊後再交出去。

### 9.10.3 用模擬器確認 RTL 的行為

RTL 是硬體，所以要用硬體的方式驗證：給它 token，看它吐出什麼。最小的 testbench 只有二十行：

```systemverilog
module tb;
  logic clk = 0, rst = 1;
  always #5 clk = ~clk;
  logic [7:0] rx_data;
  logic rx_close, rx_valid;
  wire rx_ready;
  logic out_ready = 1;
  wire [8:0] out_data;
  wire out_close, out_valid;

  Double u(.clk(clk), .rst(rst),
           .rx_data(rx_data), .rx_close(rx_close), .rx_valid(rx_valid), .rx_ready(rx_ready),
           .out_ready(out_ready), .out_data(out_data), .out_close(out_close), .out_valid(out_valid));

  // 收集吐出的 token
  always @(posedge clk)
    if (out_valid && out_ready && !out_close) $display("TOK %d", out_data);

  // 生產者：對方準備好就送下一個
  initial begin
    rx_data = 0; rx_valid = 0; rx_close = 0;
    @(negedge clk); rst = 0;
    forever begin
      @(posedge clk);
      if (rx_ready) begin
        rx_data <= rx_data + 1;
        rx_valid <= 1;
      end
    end
  end
endmodule
```

用 iverilog 跑：

```sh
iverilog -g2012 -o tb.out fir.sv tb.sv && vvp tb.out
```

吐出的 token 序列必須與程式算的一樣。這件事 Fluxa 自己做：`cargo test -p rueda-fluxa-synth --test rtl` 會把每個範例的 RTL 編譯，並且把幾個代表性任務（加倍、累加、計數、管線、網路）的 token 序列與程式比對。

### 9.10.4 接進 CI

三個層級的檢查，可以由便宜到昂貴排成三道關卡：

1. **能編譯**：每個範例的 RTL 必須是合法的 SystemVerilog（`iverilog` 編譯過）。這道關卡最便宜，抓的是「產生器壞掉」這類問題。
2. **行為一致**：代表性任務的 token 序列與程式一致（`tests/rtl.rs`）。抓的是「語意分歧」。
3. **形式等價**：RTL 與網表的等價性。這需要形式工具（yosys 的 `equiv` 之類）；目前環境沒有可用的 yosys，所以這道關卡暫時缺席——它是 M2 之後的功課。

### 9.10.5 目前的邊界

誠實地說，RTL 視圖今天覆蓋的是：

- 葉節點的任務（FSM + 埠）✓
- 任務網路（實例 + FIFO + 頂層）✓
- 陣列與 tuple 變數、記憶體、定點數 ✓

還沒有的是：

- 自動暫存器插入（所以 RTL 與網表的面積可能不同——這是 M2 的主題）；
- 資源報告（`--report`，M4）；
- 與形式工具的等價性檢查。

也就是說：RTL 視圖今天可以拿來**讀**、拿來**交接**、拿來**驗證行為**；還不能拿來取代網表進入合成流程。

### 9.10.6 練習 9.1：交接一次

1. 用 `--rtl` 產出 `examples/fir4.fx` 的 RTL。
2. 寫一個 testbench，餵一個單位脈衝，取出整段響應。
3. 把 token 序列與 `reda sim`（測試 `fir4_impulse` 的斷言）對照。
4. 在 README 或 issue 裡寫三句話說明這個 task 的介面與時序。

### 9.10.7 章末產物：一份交接包

- `*.sv`：RTL（人可讀）；
- `*.json`：網表報告（工具可讀）；
- 一份 token 序列對照表（行為可驗證）。

三者放在一起，就是「硬體是這個意思」的完整證據包。
