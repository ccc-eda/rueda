# 10.5 執行流程：sim、emu、gatesim

## 10.5.1 行為模擬

```sh
cargo build --release -p rueda
reda sim fluxa/examples/fir4.fx
reda sim --format json fluxa/examples/fir4.fx
```

`--format json` 適合接入自動化比對。輸出的結構應包含每個測試的名稱、是否通過、以及可比較的輸出欄位。

## 10.5.2 編譯後模擬

```sh
reda emu fluxa/examples/fir4.fx
reda emu --top Fir fluxa/examples/fir4.fx
reda emu -o fir.wasm --top Fir fluxa/examples/fir4.fx
```

第一個命令用編譯後的 task 執行測試；第二個指定 top；第三個輸出 WASM 供外部 harness 使用。

## 10.5.3 合成與閘級模擬

```sh
reda synth --top Fir fluxa/examples/fir4.fx
reda gatesim opt fluxa/examples/fir4.fx
reda gatesim ice40 fluxa/examples/fir4.fx
reda gatesim asic fluxa/examples/fir4.fx
```

`opt` 是一般邏輯閘網表；`ice40`、`ecp5`、`asic`、`sky130` 是不同技術映射。若你的目標是 FPGA，至少應跑對應的 FPGA 網表；若目標是 ASIC，則跑 `asic` 或 `sky130`。

## 10.5.4 三層一起跑

一個簡單的腳本可以依序執行：

```sh
set -e
F=fir.fx
TOP=Fir
reda sim "$F"
reda emu --top "$TOP" "$F"
reda synth --top "$TOP" "$F"
reda gatesim opt --top "$TOP" "$F"
reda gatesim ice40 --top "$TOP" "$F"
```

若任何一層失敗，後續命令不會執行。這是最小可用的回歸流程。

## 10.5.5 保存輸出

只跑一次不夠，必須保存：

- 命令與參數；
- 工具版本（`reda --version`）；
- 每個測試的輸出或 JSON；
- 失敗時的 seed 與最小重現案例。

這樣才能在日後比較「是這次改動造成差異」，而不是靠記憶。

## 10.5.6 一個注意事項

不同閘級後端的報告格式可能不同，但**語意比較欄位**應該一致。建議先定義一個穩定的輸出格式（例如 JSON 中的 `tests[].name`、`tests[].passed`、`tests[].outputs`），再用腳本比對，而不是直接 diff 整份文字報告。
