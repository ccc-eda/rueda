# 7.13 可讀的 RTL 視圖

網表是給工具看的：幾萬個 cell，沒有人會逐格閱讀它。但「這段 Fluxa 到底變成什麼硬體」這個問題，幾乎每個第一次做硬體的人都會問。v1.1 給了一個答案：把同一個降階結果印成 **SystemVerilog**——一個 module，資料路徑是字級的，所以它讀起來像程式，不像閘門雜燴。

```sh
reda synth --rtl out.sv --top Mac examples/mac.fx
```

### 7.13.1 一個模組長什麼樣

以 `examples/fanout.fx` 的 `Double` 為例：

```fluxa
task Double(rx: in chan<u8>, out: out chan<u9>) { for v in rx { out.send(v * 2); } }
```

印出來的 RTL（節錄）：

```systemverilog
module Double (
  input  logic clk,
  input  logic rst,
  input  logic [7:0] rx_data,
  input  logic rx_close,
  input  logic rx_valid,
  output logic rx_ready,
  input  logic out_ready,
  output logic [8:0] out_data,
  output logic out_close,
  output logic out_valid
);
  logic [2:0] state;          // 一個 block 一個狀態
  logic [7:0] recv_1;         // 跨狀態的值：暫存器
  always_comb begin
    state_next = state;
    recv_1_next = recv_1;
    rx_ready = 1'b0;
    out_data = '0;
    out_valid = 1'b0;
    case (state)
      3'd2: begin
        rx_ready = !rx_closed;                                  // 我準備好收了
        if ((rx_valid || rx_closed)) state_next = ...;            // token 到了才前進
        if ((rx_valid || rx_closed)) recv_1_next = 8'(rx_data);  // 資料收進暫存器
      end
      3'd3: begin
        out_data = ({1'b0, (recv_1)} * {7'b0, (2'd2)});           // 資料路徑：像程式
        out_valid = 1'b1;
        if (out_ready) state_next = ...;                         // 對方收下才前進
      end
    endcase
  end
```

三件事值得注意：

1. **埠就是通道**。`rx` 是輸入通道，所以 `rx_data`／`rx_close`／`rx_valid` 是輸入、`rx_ready` 是輸出；`out` 反過來。與第 12.1 節的硬體介面完全一致。
2. **狀態就是降階的 block**。`state` 的每個值對應一個 block；`case` 的分支就是那個 block 的行為。程式裡的 `for v in rx` 變成「接收 → 送出 → 回去接收」三個狀態。
3. **握手寫在明處**。`rx_valid || rx_closed` 是「有 token，或這條流結束了」；`out_ready` 是「對方收下了」。程式裡「送出會等到對方接收」的語意，在 RTL 裡是 `if (out_ready) state_next = ...` 這一行。

### 7.13.2 它保證什麼

這個 RTL 不是另一套語意，而是**同一套降階的另一种印法**：

| 項目 | 網表後端 | RTL 後端 |
| --- | --- | --- |
| 降階 | `lower.rs` | `lower.rs`（同一份） |
| 寬度 | `ty.rs` 的值域規則 | `ty.rs`（同一份） |
| 參數種類 | `gen::hw_params` | `gen::hw_params`（同一份） |
| 狀態與握手 | `gen.rs` | `gen.rs`（照抄） |
| 網路展開 | `graph::elaborate` | `graph::elaborate`（同一份） |

所以兩邊不可能對「這段程式有多寬、幾個狀態、什麼時候前進」有分歧。差別只在輸出：一個是給合成器吃的 cell，一個是給人讀的 module。

### 7.13.3 網路的 RTL

一個會 `spawn` 的任務（task 網路）也會變成 RTL：頂層 module + 每個實例的 module + 實例之間的 FIFO module。

```sh
reda synth --rtl out.sv --top Pipeline examples/pipeline.fx
```

- `FluxaFifo` 是參數化的佇列（`W` 個資料位元、`DEPTH` 個 token），語意與閘門後端的 FIFO 相同：push 端有空間就收，pop 端有東西就給。
- 任務自己的通道埠直接接到使用它的實例（中間沒有 FIFO）。
- `broadcast` 由網路自己生成一個 `Broadcast` 任務來實作。

### 7.13.4 它不是什麼

- **不是給合成器吃的。** 網表後端才是；RTL 視圖是給人讀、給人接、給人驗的。
- **不是行為描述。** 它是硬體：每個狀態一個時脈，`recv`／`send` 是握手，不是阻塞。
- **不是全部的保證。** 目前只支援能合成的那個子集（見第 12.3 節）；不支援的構造在兩個後端都會明確報錯。

### 7.13.5 讀 RTL 的檢查法

拿到 RTL 之後，依序問四個問題（與 7.12 節的六問互相對照）：

1. **埠對不對？** 每個通道參數應該剛好有四個埠（`data`／`close`／`valid`／`ready`），方向與 `in`／`out` 一致。
2. **狀態數對不對？** 狀態數應該等於降階後的 block 數；`pipeline` 的迴圈是**一個**狀態（每個時脈跑一次迭代）。
3. **前進條件對不對？** 每個狀態離開的條件，就是它的握手：`recv` 是 `valid || closed`，`send` 是 `ready`。
4. **寬度對不對？** 暫存器的位寬應該等於宣告型別的寬度，不是「大概」。

這四問答得出來，RTL 與網表對不對得上就八九不离十了；真要確認，跑模擬器比對 token 序列（見第 9.10 節）。

### 7.13.6 練習 7.4：把一個 task 的 RTL 畫成圖

取 `examples/mac.fx` 的 `Mac`（含 `pipeline(ii = 1)`），印出它的 RTL，然後：

1. 數出狀態數，說明每個狀態在做什麼。
2. 找出 `acc` 的更新式，指出乘法的兩個運算元各是多少位元、為什麼。
3. 說明 `a_ready` 在什麼條件下為 1，為什麼兩個通道要同時有效。
4. 把 `acc` 的更新式改寫成數學式 $acc + a \times b$ 然後確認位元與程式裡的 `acc += a.recv() * b.recv()` 一致。

### 7.13.7 章末產物：一份可讀的硬體說明

完成本節後，你應能交出：

- 一個任務（或網路）的 RTL 檔；
- 一張狀態圖（每個狀態：等什麼、算什麼、去哪裡）；
- 一份埠表（通道參數、方向、位寬）；
- 一句話說明「資料何時被取走、何時前進」。

這四樣東西合起來，就是「這段 Fluxa 變成什麼硬體」的完整答案——不需要打開網表。
