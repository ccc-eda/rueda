# 2.10 章末產物與下一步

本章完成的可交付物是 `saturating_scale.fx`：一個 8 位元飽和倍增 task、一份契約註解，以及一個涵蓋邊界與順序的測試。

請在交出這份檔案前逐項確認：

- [ ] 輸入與輸出通道的元素型別明確且一致。
- [ ] 中間乘積沒有被隱式窄化；飽和策略寫在程式裡。
- [ ] `spawn` 後沒有繼續使用已移動的通道端點。
- [ ] 測試包含一般值、飽和邊界、最大值與多 token 順序。
- [ ] 測試在 `reda sim` 與 `reda sim --coop` 下都通過。
- [ ] 契約註解說明 token 順序、關閉行為與轉換規則。

下一章要處理本章刻意留下的核心問題：`u8 + u8` 為什麼可能需要 9 位元，乘積為什麼可能需要 16 位元，`.sat`、`.wrap` 與 `.to` 又各代表什麼硬體選擇。當型別不再只是語法標籤，而能從值域推導出可落地的硬體寬度，Fluxa 的安全保證才真正開始。
