# 12.1 學習目標：AI 改變工作流，不改變硬體語意

## 12.1.1 生成速度不等於正確性

AI 可以在幾秒內產生一份 Fluxa 程式、一組測試或一段診斷解讀。但晶片仍然受同樣的限制：

- 每個值有一定的位寬；
- 每個通道有有限深度；
- 每個時脈週期有組合延遲上限；
- 每個裝置有資源與實體規則。

生成速度提高，不會讓這些限制消失。相反地，因為產生變快，錯誤也可能更快累積。因此，AI 時代的硬體工程更需要契約、證據與關卡。

## 12.1.2 本章要回答的問題

本章不是「如何用 AI 寫硬體」的工具教學，而是「如何把 AI 放進可審核的硬體流程」。具體問題包括：

- 如何讓規格成為唯一事實來源？
- agent 可以扮演哪些角色，各自需要什麼驗收條件？
- 哪些工作可以大幅加速，哪些必須人工把關？
- 如何防止 agent 幻想未實作的 API 或版本？
- 如何設計自動化閘門，讓 AI 的產出必須通過證據？

## 12.1.3 學習目標

完成本章後，你應該能夠：

- 將自然語言需求拆成可檢查的契約；
- 設計有明確限制、證據與驗收命令的 agent 任務；
- 用分級人工關卡控制高風險變更；
- 建立可追溯、可重現、可回退的流程；
- 辨認 AI 輔助開發的盲點與責任邊界。

## 12.1.4 一個核心原則

全章可以用一句話總結：

> AI 可以加速產生候選方案，但正確性必須由契約、測試與證據共同決定。

這句話不是反對使用 AI，而是把 AI 放在它最擅長的位置：產生、整理、比較與解釋；同時把不可委託的部分留給可驗證的工程流程。
