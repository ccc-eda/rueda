# 4.15 本章回顧

本章的核心可以濃縮成五句話：

1. `task` 是程序網路的節點，通道是有界 FIFO，token 是沿 FIFO 流動的資料。
2. `send` 與 `recv` 都是阻塞式操作；FIFO 深度改變等待與吞吐，不應改變邏輯 token 序列。
3. 通道端點是線性資源；`spawn` 會移轉所有權，`broadcast` 會消耗來源接收端。
4. 方向與元素型別必須完全相符；`broadcast` 讓每個分支收到完整序列，不是競爭式消費。
5. 背壓會沿資料流向上游傳遞；死結則是所有 task 都等待、卻沒有任何 task 能前進。

下一章將把這張網路放進行為模擬器：觀察原生排程器與合作式排程器如何執行同一個 KPN，如何用 `assert`、trace 與 stats 建立可重現 oracle，以及如何從等待圖定位死結。網路形狀說清楚「資料如何流動」；行為模擬則讓我們證明「每次流動的結果都符合契約」。
