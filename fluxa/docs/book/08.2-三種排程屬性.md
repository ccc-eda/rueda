# 8.2 三種排程屬性

Fluxa 把三種常見的硬體意圖直接放在迴圈上：

```fluxa
pipeline(ii = 1) for x in input { /* 每拍可啟動一次 */ }
unroll for i in 0..4 { /* 空間上展開四份 */ }
serial for i in 0..4 { /* 每一輪形成時序邊界 */ }
```

這三個屬性表達的是設計者對「空間與時間如何分配」的決定，不是最佳化開關。它們也不應讓同一份 token 契約產生不同結果。

### 8.2.1 `pipeline(ii = n)`：要求啟動間隔

`pipeline(ii = n)` 宣告「這個迴圈要能以指定的啟動間隔進行」。在目前 v1.0 中，真正有明確實作路徑、也最值得使用的目標是：

```fluxa
pipeline(ii = 1) for s in x {
    let y = transform(s);
    out.send(y);
}
```

它表達的是：

> 當這個迭代需要的輸入都可用，而且輸出有空間時，可以在一個時脈週期內啟動下一個迭代。

因此，一個迭代可以在同一個管線狀態中等待多個不同通道的輸入，計算結果，並把多個不同通道的輸出交給外部。**「每個迭代最多使用同一通道一次」**是重要的結構限制：目前每條通道每拍最多傳送一個 token，因此同一通道在一輪內收兩次或送兩次，就不能直接塞進 II = 1 的單一管線狀態。

`pipeline` 的另一個重要含意是排程要求，而不是最佳化保證。即使 `pipeline(ii = 1)` 通過檢查，也不能推論：

- 乘法器與加法樹一定符合目標時鐘；
- 工具一定會使用 DSP block；
- 輸出一定在固定幾拍後出現；
- `ii = 2` 的語意一定等於每兩拍啟動一次。

第一、二點需要後端時序與資源報告；第三點需要量測延遲；第四點是 v1.0 的已知限制，稍後會單獨說明。

### 8.2.2 `unroll`：以面積換並行度

`unroll` 要求在合成時把固定次數的迴圈展開成多份硬體：

```fluxa
unroll for i in 0..4 {
    let p = product[i] * coefficient[i];
    // 四份乘加邏輯同時存在
}
```

展開的好處是迭代之間沒有循序控制，適合乘加樹、固定係數的 FIR taps，或把幾個獨立操作放到同一個資料路徑。代價也很直接：

- 複製乘法器、加法器與多工器；
- 複製或增加控制訊號；
- 可能讓輸出選擇器變長；
- 若複製的存取指向同一個記憶體，可能撞上讀埠或寫埠限制。

因此，`unroll` 不是「寫四次程式」而已；它要求工具知道哪些資源真的可以複製。純組合資料路徑最適合這個屬性。含通道操作的迴圈仍受每拍每通道一個 token 的硬體握手限制，不能靠展開語法繞過。

Fluxa 也提供範圍物件的 `.unrolled()` 方法：

```fluxa
let acc = (0..4).unrolled()
                 .map(|k| win[k] * COEF[k])
                 .tree_sum();
```

這裡的 `.unrolled()` 表達「把四個固定 tap 展開成四個乘法路徑」，而 `.tree_sum()` 再把乘積組成平衡加法樹。模擬時結果與一般迴圈相同；合成時才產生空間並行的資料路徑。

### 8.2.3 `serial`：以時間換面積

`serial` 要求每輪迭代形成明確的時序邊界：

```fluxa
serial for i in 0..4 {
    acc = acc + term(i);
}
```

它把原本可以同時存在的運算，改成由 FSM 依序完成。硬體可以重用一組乘法器與加法器，因此面積較小；代價是迭代不能以 II = 1 重疊，吞吐量下降，延遲通常也會增加。

在目前的硬體降階中，`serial` 迴圈會被轉成循序狀態；通道操作仍然形成額外的握手邊界。精確的每輪週期數不應只靠讀原始碼猜測，應以合成後的網表或硬體模擬量測。若某段運算需要多個時脈，還要在 task 內明確安排狀態，而不是把 `serial` 當成 magical 的多週期指令。

### 8.2.4 排程選擇速查

| 需求 | 優先考慮 | 原因 |
| --- | --- | --- |
| 每拍一個樣本 | `pipeline(ii = 1)` | 直接表達啟動間隔要求 |
| 四個固定 tap 同時計算 | `unroll` | 以空間換時間 |
| 運算器昂貴、吞吐可接受 | `serial` | 重用硬體，減少複製 |
| 需要保留前一迭代歷史 | `@reg` | 明確表達暫存器與迭代提交 |
| 需要跨迭代累加 | `carry` 或型別化 `let mut` | 讓值域分析看見累加相依 |
| 需要大量隨機存取 | `mem` | 以記憶體取代龐大 FF 陣列 |

這個表不是互斥清單。FIR 往往同時使用 `pipeline(ii = 1)`、`.unrolled()`、`tree_sum()` 與 `@reg`；理解每個屬性處理的是哪一個時間或空間問題，才能組合出可解釋的架構。
