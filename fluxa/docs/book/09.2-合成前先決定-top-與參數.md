# 9.2 合成前先決定 top 與參數

## 9.2.1 一個檔案裡可能有很多 task

Fluxa 檔案可以同時包含 helper、`test` 與多個 `task`。合成器必須知道哪一個 task 是硬體的入口。`reda synth` 的預設規則是「最後一個非 test 的 task」，但在有多個可合成元件時，明確指定更安全：

```sh
reda synth --top Fir fluxa/examples/fir4.fx
reda fpga --top Fir --pcf pins.pcf --bin fir4.bin fluxa/examples/fir4.fx
reda asic --top Fir --pdk sky130 --gds fir4.gds fluxa/examples/fir4.fx
```

若指定了不存在或不可合成的 task，工具應明確報錯，而不是默默挑另一個。這點很重要：top 選錯時，產生的網表可能仍然「成功」，但行為與預期完全不同。

## 9.2.2 什麼是可合成的 task

合成器只接受能靜態展開的硬體結構。Fluxa v1.0 對下列構造明確不支援合成：

| 構造 | 合成結果 |
| --- | --- |
| 遞迴 | 明確報錯，不產生網表 |
| 執行期才決定 spawn 次數 | 明確報錯；spawn tree 必須可靜態展開 |
| 浮點數 | 明確報錯 |
| `stage` 層 | 明確報錯 |
| type generic 參數 | 明確報錯；硬體元素型別須使用 const generic |
| 通道陣列參數 `[chan<T>; N]` | 僅模擬支援，不合成 |
| `print` | 呼叫被丟棄，不產生硬體邏輯 |

因此，「可合成」不是一個模糊的品質形容詞，而是一組可以被檢查的語言限制。寫硬體時，先把這些限制當成邊界，再談最佳化。

## 9.2.3 用 `--param` 把參數固定成常數

頂層 task 的 scalar 參數預設會變成輸入埠。若某個參數在硬體中是固定的（例如 FIR 的 tap 數、矩陣大小、常數表），可以用 `--param` 固定：

```sh
reda synth --top Fir --param TAPS=4 fluxa/examples/fir4.fx
```

固定後，該參數不再形成外部埠，而是合成時的常數。這會影響位寬推導、迴圈展開與資源數量，因此同一個 task 在不同參數下可能產生完全不同的硬體。

`--param` 也可以放陣列，例如把程式或係數表變成 ROM：

```sh
reda synth --top Fir --param 'COEF=image([1, 2, 3, 4])' fir.fx
```

## 9.2.4 const generic 與單體化

Fluxa 的 const generic 讓「形狀」成為編譯期常數：

```fluxa
task Dot<const N: usize>(a: chan<i8> in, b: chan<i8> in, y: chan<i32> out) {
    let mut acc: i32 = 0;
    for _ in 0..N {
        acc += a.recv() * b.recv();
    }
    y.send(acc);
}
```

合成器會依實際使用的 `N` 產生對應的單體。這表示 `Dot::<4>` 與 `Dot::<16>` 是兩個不同的硬體實例，而不是一個執行期可調的通用電路。

這也是為什麼 `--param` 與 const generic 必須搭配使用：若 `N` 沒有被固定，合成器就不知道要展開幾份邏輯，也無法推導迴圈次數與位寬。

## 9.2.5 先列出合成清單

在按下合成之前，先寫下這份清單：

- top task 是哪一個？
- 哪些參數是外部埠，哪些要用 `--param` 固定？
- 哪些 task 會被 spawn，總共幾個實例？
- 內部通道各有多深，會變成多少 FIFO？
- 預期的資源上限是多少？

這份清單會在後面的報告中被逐項驗證。若某個數字與預期不同，就是除錯的起點，而不是等到位元流燒進板子後才發現。
