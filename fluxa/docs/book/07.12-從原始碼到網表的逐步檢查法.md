# 7.12 從原始碼到網表的逐步檢查法

遇到「這段 Fluxa 到底變成什麼電路」時，不要只看最終網表。可以依序問六個問題：

1. **這是值還是程序？**  
   `fn` 通常內嵌；`task` 成為有狀態實例。

2. **哪些操作可能等待？**  
   `recv`、`send`、`close` 形成狀態邊界。

3. **哪些值跨越狀態邊界？**  
   只有它們通常需要 task 變數 FF 或 pending 值。

4. **哪些條件只選擇資料？**  
   純算術分支形成比較器與多工器，不必分裂 FSM。

5. **哪些迴圈要展開，哪些要循序？**  
   固定小迴圈可展開；未知次數或含等待的迴圈使用 FSM 計數。

6. **task 網路有哪些實例與 FIFO？**  
   內部通道要核對方向、型別、深度與面積。

這六個問題，正好對應控制流、資料流與網路三個層次。

### 7.12.1 練習 7.1：手畫三狀態 task 的 CFG

請為下列 task 手畫 CFG，標出等待點、join 點與 task 結束時關閉輸出的位置：

```fluxa
task Three(
    x: in chan<i8>,
    y: out chan<i8>,
    z: out chan<i8>
) {
    for v in x {
        if v >= 0 {
            y.send(v);
        } else {
            z.send(-v);
        }
    }
}
```

檢查重點：

- `recv` 與兩個 `send` 都是等待點；
- `if` 形成兩條控制路徑；
- 兩條路徑完成後回到接收；
- 輸入關閉時走出口；
- 出口必須分別關閉 `y` 與 `z`。

### 7.12.2 練習 7.2：把 `match` 改寫成 `if` 鏈

將：

```fluxa
match mode {
    0 => result = a + b,
    1 => result = a - b,
    _ => result = 0,
}
```

改寫成 `if / else if / else`，比較兩種形式的控制與資料結構：

- 純資料 `match` 可以由多個比較器與多工器形成，不必增加 FSM 狀態；
- `if` 鏈同樣可用巢狀多工器形成；
- 若 arm 內含通道操作，兩者都要分裂控制路徑；
- 重寫不應改變值域、優先順序與 guard 語意。

### 7.12.3 練習 7.3：閱讀 FIR 的面積分解

執行：

```sh
reda synth --top Fir4 --format json examples/fir4.fx
```

回答：

1. 有多少個 task 實例？
2. 每個 task 的狀態與資料路徑分別貢獻多少 cell？
3. FIFO 占總 cell 數多少？
4. 若結果與另一版差很多，是演算法改變、通道深度改變，還是排程屬性改變？

### 7.12.4 章末產物：FIR 狀態／資料路徑草圖

完成本章後，你應能交出一張包含下列資訊的 FIR 草圖：

- `recv`、計算、`send`、close 與 halt 狀態；
- 每個狀態等待什麼條件；
- 乘、加、移位、捨入與飽和的資料路徑；
- `x1`、`x2`、`x3` 等跨狀態值；
- FSM 狀態 FF、task 變數 FF 與 FIFO entry FF 的區別；
- 一輸入一輸出的 token 契約，以及輸入關閉如何傳成輸出關閉。

這張草圖不需要包含目標 FPGA 的 LUT 編號，也不需要先決定最高頻率；它的任務是把**語意上的等待與資料依賴**準確映射成**硬體上的控制與儲存**。第 8 章才會在這張草圖上加入 initiation interval、管線深度、累加器與記憶體等排程與資源決策。
