# 2.9 練習

### 練習 2.1：改成無符號輸出，並列出所有會改變的型別

原始問題是「把倍增 task 改成無符號輸出」。本章的 `SaturatingDouble` 已經使用 `u8`，所以請改做一個更有區別的版本：將輸入或中間乘積改成 `i8`，觀察：

1. 負數乘 2 的值域為何？
2. 結果若要飽和到 `i8`，上下界分別是多少？
3. 通道參數、輸入向量、乘法表達式與轉換方法各要如何修改？
4. 如果硬體允許回繞，轉換策略會如何不同？

最後列出所有會改變的型別，不要只改通道宣告。

### 練習 2.2：以 const generic 寫固定長度縮放器

寫一個 task，輸入是一串 `u8`，輸出是一串 `u16`，每個輸出是輸入乘上一個固定係數。請使用：

```fluxa
task FixedScale<const FACTOR: u16>(
    x: in chan<u8>,
    y: out chan<u24>
) { /* ... */ }
```

並完成至少三個測試：係數 1、2，以及一個會讓 `u8 × u16` 有必要採用的值域案例。再回答：若要把這個元件送進合成器，為什麼 `FACTOR` 應是 const generic 而不是 type generic？

### 練習 2.3：把 happy-path 測試改成契約測試

把一個只測中間值的測試改寫成契約測試，至少檢查：

- token 數量；
- token 順序；
- 邊界值；
- 通道關閉後不再出現新 token。

### 練習 2.4：多檔組織

把 `SaturatingDouble` 與它的測試拆成兩個 `.fx` 檔：

```sh
reda sim component.fx component_test.fx
reda sim component.fx component_test.fx --test saturating_double_contract
```

記錄兩個檔案中的命名規則，並解釋為什麼 `use` 在 v1.0 不能取代嚴格的命名規則。
