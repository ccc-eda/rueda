# 9.5 FPGA 流程：LUT、佈局繞線與位元流

## 9.5.1 FPGA 的基本資源

FPGA 不是把邏輯閘直接印在晶片上，而是提供可重複配置的資源：

| 資源 | 用途 |
| --- | --- |
| LUT | 實作組合邏輯（例如 4 輸入布林函數） |
| FF | 實作正反器與暫存器 |
| Carry | 實作快速進位鏈，適合加法與比較 |
| Block RAM | 實作較大的記憶體與 FIFO |
| DSP（部分裝置） | 實作乘法與乘加 |

`reda fpga` 的 iCE40 流程會把網表映射到 `SB_LUT4`、`SB_CARRY`、`SB_DFF*` 與 `SB_RAM40_4K`；ECP5 流程則映射到 `LUT4`、`CCU2C` 與 `TRELLIS_FF`。

## 9.5.2 一個最小 FPGA 流程

以 iCE40 為例，只產生通用網表統計：

```sh
reda synth --top Fir fir.fx
```

要產生位元流，需要提供腳位約束與輸出檔：

```sh
reda fpga --top Fir --pcf pins.pcf --bin fir.bin fir.fx
```

若使用 ECP5：

```sh
reda fpga --top Fir --arch ecp5 --lpf pins.lpf --bit fir.bit fir.fx
```

`--bin` 與 `--bit` 只是不同裝置的位元流格式。它們都代表「這個設計已經被映射到特定裝置、完成佈局繞線，並打包成可燒錄的檔案」。

## 9.5.3 佈局與繞線在做什麼

合成只決定「用哪些 LUT 與 FF」，佈局繞線則決定「把它們放在晶片哪裡、用哪些線連起來」。這一步會直接影響時序：

- 距離越遠，連線延遲越大；
- 擁塞越嚴重，繞線可能被迫走更長的路徑；
- 時脈樹的分布會影響時脈偏移。

因此，同一個網表在不同裝置、不同腳位約束、不同種子下，可能得到不同的最高頻率。位元流能產生，不代表時序目標已達成。

## 9.5.4 腳位約束

FPGA 的 `pcf` 或 `lpf` 檔把設計中的訊號連到實體接腳。若某個通道埠沒有被約束，工具可能：

- 自動挑一個腳位；
- 或報錯要求補上約束。

對 `valid/ready` 串流介面而言，至少要約束 `clk`、`rst`、資料線、`valid`、`ready` 與 `close`。少約束一條線，就可能出現「電路看起來會動，但資料永遠不握手」的現象。

## 9.5.5 讀懂 FPGA 報告

一份可用的 FPGA 報告至少要看：

| 項目 | 問題 |
| --- | --- |
| LUT 使用量 | 是否接近裝置上限？ |
| FF 使用量 | 是否有不必要的暫存器？ |
| BRAM 使用量 | FIFO 或記憶體是否過大？ |
| 時序 | 最差路徑是否滿足目標頻率？ |
| 腳位 | 所有埠是否都正確約束？ |

如果時序不通過，先不要急著改程式。先確認最差路徑落在哪一種邏輯：乘法、加法樹、握手或多工器。不同原因有不同修正方式：

- 乘法／加法路徑太長：改排程、共享運算或增加暫存邊界；
- 握手邏輯太複雜：簡化通道操作或降低平行度；
- 繞線太長：調整腳位或佈局種子；
- 資源超限：降低展開或縮小位寬。

## 9.5.6 FPGA 不是終點

FPGA 流程的價值在於快速驗證硬體結構與介面。它仍然需要第 10 章的閘級模擬與等價檢查，才能宣稱「功能正確」。位元流只證明工具能把設計放進裝置，不證明設計符合規格。
