# 2.5 編譯期參數化：const generic 與 type generic

### const generic：可合成的形狀參數

```fluxa
task Scale<const FACTOR: u16>(
    x: in chan<u8>,
    y: out chan<u24>
) {
    for v in x {
        y.send(v * FACTOR);
    }
}
```

這裡 `FACTOR` 是編譯期參數，可以出現在運算中。輸入最大為 255，係數最大為 65535，所以乘積最多需要 24 位元；`u24` 能完整容納這個值域。

呼叫時使用 turbofish：

```fluxa
spawn Scale::<3>(rx, ty);
```

在**模擬**中，`::<...>` 的常數引數可由呼叫點提供；在**合成**時，同一個元件的泛型值必須成為固定的編譯期參數，工具才能產生一個確定的網表。

通道深度也能由 const generic 控制，但要把它用在真正建立內部通道的位置。例如：

```fluxa
task Offset(x: in chan<u24>, y: out chan<u24>) {
    for v in x {
        y.send(v + 1);
    }
}

task ScaleThenOffset<const DEPTH: u32>(
    x: in chan<u8>,
    y: out chan<u24>
) {
    let (mid_tx, mid_rx) = chan::<u24>(depth = DEPTH);
    spawn Scale::<3>(x, mid_tx);
    spawn Offset(mid_rx, y);
}
```

現在 `DEPTH` 真正決定兩個 stage 之間 FIFO 的容量；呼叫端則用 `spawn ScaleThenOffset::<4>(...)` 固定這個形狀。

### 用 const generic 決定位元寬

需要依泛型參數決定整數位寬時，不要用 type generic，而要用值域表達：

```fluxa
task WideCopy<const WIDTH: u32>(
    x: in chan<int<-(1 << (WIDTH - 1)) ..= (1 << (WIDTH - 1)) - 1>>,
    y: out chan<int<-(1 << (WIDTH - 1)) ..= (1 << (WIDTH - 1)) - 1>>
) {
    for v in x {
        y.send(v);
    }
}
```

`WIDTH = 8` 時，這個型別就是 `i8`；`WIDTH = 16` 時就是 `i16`。這種寫法可模擬也可合成。

也可以讓 const generic 決定陣列大小：

```fluxa
task Histogram<const BINS: u32>(
    x: in chan<int<0..=BINS - 1>>,
    counts: out chan<u32>
) {
    let mut bins: [u32; BINS] = [0; BINS];
    for v in x {
        bins[v] = bins[v] + 1;
    }
    for n in bins {
        counts.send(n);
    }
}
```

這裡 `BINS` 的值必須在建立該 task 之前已知。執行期才決定 `spawn` 幾次，不受合成支援；固定次數的 `spawn` 迴圈則可以形成靜態 spawn tree。

### type generic：模擬可用，合成不可用

Fluxa v1.0 也接受型別參數：

```fluxa
task Identity<T>(x: in chan<T>, y: out chan<T>) {
    for v in x {
        y.send(v);
    }
}
```

模擬器可以接受這種形式（未具體化的參數在內部以 `Any` 處理），但**目前合成器不能**為 type generic 產生硬體。原因是硬體位元寬、埠寬與記憶體形狀必須在產生網表前固定。

因此，可合成的元件應遵守：

| 參數化需求 | 應使用 | 能否合成 |
| --- | --- | --- |
| 固定係數、固定長度、固定通道深度 | `const` generic | 可以 |
| 依參數改變整數位寬 | `const` generic 計算值域 | 可以 |
| 純模擬中的泛型資料結構 | `type` generic | 暫時不可以 |
| 執行期決定 `spawn` 數量 | 無法用泛型解決 | 不可以 |

### 一個刻意失敗的參數化例子

```fluxa
// 錯誤：硬體通道元素的位寬不能由尚未具體化的 T 決定。
task GenericCopy<T>(x: in chan<T>, y: out chan<T>) {
    for v in x {
        y.send(v);
    }
}
```

這段在模擬器可接受，但送進 `reda synth` 時會拒絕 type generic。這個邊界值得記住：**語法能解析，不代表目前能變成硬體。**
