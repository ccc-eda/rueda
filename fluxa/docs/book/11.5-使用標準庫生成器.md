# 11.5 使用標準庫生成器

## 11.5.1 標準庫不是黑盒 IP

Fluxa 標準庫的元件本身也是 Fluxa task 網路：

- 行為模擬、閘級模擬、`reda check` 與合成都照常工作；
- 使用者自己定義的同名 task 優先；
- 程式出現 `std::` 時，載入器會自動併入標準庫檔案。

這表示你可以閱讀、檢查、甚至修改它的結構，而不是只能相信一個二進位黑盒。

## 11.5.2 `std::SystolicMatmul`

```fluxa
task Mm4(a: in chan<i8>, b: in chan<i8>, c: out chan<i32>) {
    spawn std::SystolicMatmul::<4, 8, 32>(a, b, c);
}
```

使用時要注意：

- `a`、`b` 必須 lockstep；
- `CW` 要足以容納 `N` 個乘積之和；
- 累加使用 wrap，程式不檢查溢位；
- 內部通道深度都是 2。

這些都是契約的一部分。標準庫不會替呼叫端推導 `CW`，也不會在溢位時報錯。

## 11.5.3 `std::Window3x3`

```fluxa
task Blur8x6(x: in chan<u8>, y: out chan<u8>) {
    let (tw, rw) = chan::<[[u8; 3]; 3]>(depth = 2);
    spawn std::Window3x3::<8, 6, 8>(x, tw);
    spawn Blur(rw, y);
}
```

它只輸出內部像素，並使用兩條 line buffer。後處理必須另外寫一個 task，因為目前還不能把函式或任務當參數傳遞。

## 11.5.4 面積案例

標準庫文件記錄了一個實際比較：在 iCE40 HX8K、`N = 4`、`AW = 8`、`CW = 32` 時，`std::SystolicMatmul` 約使用 16,011 個 LC，而 AI 臨場手接的版本約 37,233 個 LC。HX8K 只有 7,680 個 LC，因此兩者都放不進 HX8K。

這個例子說明兩件事：

1. 標準庫不保證能放進小裝置；
2. 面積最佳化是另一個獨立的工程問題，不是「用了標準庫就解決」。

大部分面積在 PE，每個約 1,162 個通用閘；乘法器使用 LUT。若要縮小，可能需要改變 PE 結構、降低 `N` 或改用不同的資料流架構。

## 11.5.5 使用標準庫的紀律

把標準庫當成一般元件對待：

- 先讀它的契約，不要只看介面；
- 用 `reda check` 與測試確認它在你的參數下成立；
- 記錄使用的版本；
- 若它不滿足需求，考慮自己寫一個可檢查的 task 網路，而不是在標準庫外包一層不可見的假設。
