## 閱讀順序與使用方式

1. **先讀 [01](01-推廣策略.md)**：決定「賣給誰」「先做什麼」。它回答的是商業與社群問題，行動項目最急。
2. **再讀 [03](03-共通基礎建設.md)**：任何跨領域嘗試都會先卡在這裡。它是所有其他計畫的共同前置。
3. **最後讀 [02](02-相鄰領域擴張.md)**：長期版圖。它列出六個相鄰領域各自成立的理由、最小實驗、缺口與坑。

## 文件狀態

這三份都是**提案**，不是已核准的計畫。每一份都標示了「既有事實」與「提案」：

- **既有事實**：可在 repo 內驗證（語言規格、實作、實驗紀錄、論文）。
- **提案**：尚未實作或尚未量測的想法，帶有風險與成功判準。

引用數字時，請以 `../spec/ai-bench.md`、`../spec/std.md`、`../spec/synthesis-plan.md`、`../spec/emu-plan.md` 與 `../../docs/note/emu-compare.md` 為準；所有數字都可以用 [03](03-共通基礎建設.md) 附錄列出的命令重現。

## 三句話版本

- **推廣**：Fluxa 的價值只在「很小、很貴、很難做對」的市場裡被看見——所以主打 AI 產生的硬體、驗證與參數化硬體生成器，並且「插進既有流程」而不是「取代既有流程」。
- **擴張**：可攜的不是語言，是「確定性 + 靜態上界 + 精確寬度 + 能力隔離 + 可重放」這五個屬性。
- **底線**：為了通用而稀釋硬體子集，會讓 Fluxa 變成「C/C++ + 合成子集」，也就是 HLS 語言最被詬病的樣子。
