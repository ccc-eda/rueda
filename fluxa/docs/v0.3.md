# Fluxa 模擬器 v0.3 設計：RV64G + MMU

狀態：**v0.3 完成（M1–M6）**。本文件前半是原始設計藍圖，實作中的取捨與偏離（例如沒有獨立的 Translate task）記錄在 §10 各里程碑的實作筆記。

## 1. 目標與範圍決策

在 v0.2 的 RV32I 核心（`rv32i/`）經驗上，實作一顆 **RV64G + 特權架構 + Sv39 MMU** 的行為級處理器。

| 決策 | 內容 | 理由 |
|---|---|---|
| ISA | RV64G = RV64IMAFD + Zicsr + Zifencei | 「G」的定義即此 |
| MMU | Sv39（含 2MB / 1GB 巨頁）+ 統一 TLB + 硬體頁表走訪 | 特權規格標準；Sv48 留作後續 |
| 特權模式 | M / S / U 三層，含 trap 進出（`mret`/`sret`）、`ecall`/`ebreak` | MMU 必然牽動 S/U |
| Hart 數 | **單 hart** | 多 hart 的 AMO/LR-SC 排程會考驗確定性，屬 v0.4+ |
| C 擴充 | 不做 | 壓縮指令與行為語意無關，只影響取指編碼 |
| PMP / 中斷 | 不做；timer 中斷僅列為選配（以「已退休指令數」驅動，見 §8） | 控制範圍 |
| F/D 實作 | **整數精確 IEEE-754**（見 §6） | 見下方可行性分析 |

非目標：效能、週期精確度（`stage` 層本模擬器不做）、亂序、多核。

## 2. 對 v0.2 rv32i 的延續與差異

延續 rv32i 的骨架與紀律：

- 四級流程 `Fetch → Decode → Execute → Mem`，深度 1 的 FIFO 相連，寫回 FIFO 深度 `WBD`（const 泛型，深度不足 → 死結，如 `err_wb_depth.fx`）。
- Decode 持有暫存器檔與記分板（in-order 停等解決資料相依）；分支/JALR 由 Execute 送回 redirect token（停等，無分支預測）。
- 結束協定：ECALL/EBREAK/非法指令 → 傾印固定長度狀態 token。
- 組譯器即函式：參數型別 = 編碼欄位寬度，超界立即值在組譯時被位寬檢查擋下。

RV64 帶來的差異：

- 資料路徑 u32 → u64；移位量 6 位元；`li` 需 20 位元 → `lui + addiw` 展開（64 位常數用 `lui/addi/slli` 標準序列）。
- **新增 W 型指令**（`addiw`/`slliw`/…：32 位元運算結果符號擴展到 64 位元）— Fluxa 精確整數下寫法為
  `(imm as i32).wrap::<i32>() as i64` 的顯式窄化組合。
- 陷阱傾印長度改為 68（cause/pc/retired/stalls + x0..x31 + f0..f31 低位）。

## 3. 整體架構（tasks 與 channels）

```
                                    satp, SFENCE.VMA
              ┌──────────────────────────────────────────┐
              │                                          ▼
 Fetch ──► Decode ──► Execute ──► Mem ──► WB
   ▲         ▲  │        │  │      │
   │redirect │  │wb      │  │(load)│          Translate（TLB + 頁表走訪）
   │         │  ▼        ▼  ▼      │            ▲ pa/fault   │ walk rd/wr
   └─────────┴──(CSRs 在 Decode；trap 由 Decode 統一發射)     Mem（實體記憶體）
```

| Task | 持有狀態 | 職責 |
|---|---|---|
| `Fetch` | pc、指令映像 | 逐指令送 `Decode`；取指位址先過 `Translate`（U 模式時）；JAL 自算目標，分支/JALR 等 redirect |
| `Decode` | 暫存器檔、記分板、**CSR 檔**、fcsr | 譯碼、資料相依停等、**trap 統一入口**（更新 mepc/mcause/…、跳 mtvec/stvec）、`mret`/`sret`、送 `satp`/`SFENCE.VMA` 給 Translate |
| `Execute` | — | ALU、分支判斷、位址計算、CSR 讀寫（經 Decode 或獨立回路） |
| `Mem` | 資料記憶體、MMIO、保留區（LR/SC） | load/store/AMO、LR/SC、把 walk 讀寫與管線存取送往實體記憶體 |
| `Translate` | TLB（`mem` 陣列 + 線性搜尋） | VA→PA；miss 時走訪頁表（經 `Mem` 的 walk 埠）；回 pa 或頁錯誤；處理 SFENCE.VMA |
| `WB` / 回寫 | — | 依程式順序寫回（沿用 rv32i：Decode 記分板等 wb token） |

單 hart + in-order + 停等的結果：**任一時刻至多一個未完成的記憶體存取或一次走訪**，
這是 Translate／Mem／Bus 之間可以簡化仲裁的關鍵（見 §7 死結紀律）。

## 4. CSR 檔與特權流程

- CSR 檔放 `Decode`（單 hart、in-order，所有 CSR 存取與 trap 都能在此序列化）。
  用 `mem<u64, N>` 以 12 位元位址索引，保留區為非法位址 → 非法指令例外。
- 最小集合：`mstatus`（MIE/MPIE/MPP 等子集）、`mtvec`/`mepc`/`mcause`/`mtval`、
  `misa`、`mhartid`、`mscratch`、`mie`/`mip`（唯讀統計）、`sepc`/`scause`/`stval`/`stvec`/`sscratch`、
  `sstatus`（= mstatus 視窗）、`satp`、`fflags`/`frm`、`mcounteren`/`scounteren`（存取權檢查）。
- Trap 流程：例外偵測點（Fetch：取指頁錯誤；Decode：非法指令/ecall/ebreak/CSR 權限；
  Mem：載存頁錯誤、未對齊、存取錯誤）→ 送 trap token 回 Decode（帶 cause/tval/pc）→
  Decode 排空管線（沿用 rv32i 記分板排空迴圈）→ 依 `medeleg`/`sedeleg` 子集路由到 M 或 S →
  更新 CSR → pc 設為 `tvec`。`mret`/`sret` 在 Decode 還原模式與 pc。
- `SFENCE.VMA`（含 rs2=ASID / rs1=特定位址的過濾語意）與 `satp` 寫入：
  Decode 送命令 token 給 Translate 並**等 ack**——in-order 停等下，此時無在途轉譯，順序可固定。

## 5. Sv39 MMU 細節

- 虛擬位址 39 位元（va[38:12] 為 VPN），三層頁表；PTE 64 位元：`V R W X U G A D` + PPN。
  支援葉 PTE 的 4KB / 2MB / 1GB 巨頁；非葉但 R/W/X 任一為 1 → 保留編碼（非法）。
- 檢查順序依特權規格：V 位 → 權限（U 位 vs 當前模式、SUM/MXR 由 mstatus 控制）→
  A/D 位（本實作**硬體自動設 A/D**，行為模擬中成本極低、可省去軟體 setter 測試）。
- 例外：`load-page-fault(13)`、`store/AMO-page-fault(15)`、`instruction-page-fault(12)`；
  走訪中讀到不可寫的頁表項位置 → `load-access-fault`（簡化，記錄於實作筆記）。
- `Translate` 內的 TLB：`mem<u64, TLB_ENTRIES>` 三路並聯（tag/pte/層級），線性搜尋用 `unroll`。
  **TLB 內容只影響停等次數，不影響任何輸出**——翻譯結果是位址的純函數
  （SFENCE.VMA/satp 命令已把失效時序固定化）。這讓「TLB 大小 1 vs 16 跑出相同結果」
  成為確定性的直接測試（見 §9）。

## 6. F/D：整數精確 IEEE-754

可行性分析（本節結論奠基於已驗證的模擬器能力）：

- 模擬器內建 `Value::Float(f64)` 只支援 `+ - * /` 與比較（`value.rs` 的 `binop`），
  **沒有位元重解讀（bitcast）**，也沒有捨入模式控制；而 F/D 需要
  FMV.X.W/D、以位元形式存進整數記憶體體系、NaN payload、四種捨入模式與 fflags。
  → **不可行**用內建 f64 實作 F/D。
- 反過來，Fluxa 的 120 位元精確整數 + `for`/`unroll` 迴圈非常適合把 IEEE-754
  當成「純整數演算法」實作：解碼（sign/exp/frac）→ 對齊/運算 → 捨入 → 編碼，
  全程 u64 位元模式，記憶體就是普通 u64。

實作計畫（全部 `comb fn`，輸入輸出皆 u64 位元模式）：

| 運算 | 方法 |
|---|---|
| fadd/fsub | 兩運算元展開成 (sign, exp, 53+guard 位有效數) → 對齊 → 120 位整數加減 → 依 `frm` 捨入 → flags（NV/DZ/OF/UF/NX）逐一精確判定 |
| fmul | 53×53 → 106 位精確積（120 位整數放得下）→ 捨入 |
| fdiv | 移位-減法長除法迴圈產生 55+ 位商 → 捨入 |
| fsqrt | 整數牛頓/逐位元法 |
| fcvt 系 | 與 120 位整數互轉，範圍外依捨入模式夾限 → NV/OF |
| fmin/fmax/fclass/fcmp | 對解碼後的 (類別, 位元模式) 比較；NaN 規則依規格 |
| NaN | canonical quiet NaN 產生與 payload 傳播規則按 spec；`fcsr.fflags` 累積在 Decode |
| 非正規數 | 完整支援（flush-to-zero 不做，除非測試需要再列選項） |

驗證策略：以「對照組」測試為主——每個運算的捨入邊界案例（最大/最小正規數、
非正規數、半途捨入、∞、NaN payload）逐一列出手算期望值；
再以「性質測試」補強：`fadd(a,b) 與 (b,a)` 對稱性、單調性抽樣等。

## 7. 確定性與死結紀律

沿用 v0.2 的原則並新增 MMU 相關約束（深度不足要像 `err_wb_depth.fx` 一樣有 err_* 示範）：

- 階段間 FIFO 深度 1；`WBD` 寫回深度需 ≥ 管線可同時在途寫回數（`MAX_INFLIGHT` 上界不變）。
- Translate 的 walk 讀寫通道：單 hart 停等 ⇒ 走訪時管線必然已停在等待翻譯，
  `Mem` 以「管線存取優先、否則服務 walk 埠」的固定順序服務 → 無競態、無需額外深度。
  走訪最多 3 次讀 + A/D 寫回，walk_resp 深度 1 即足夠；err_* 示範驗證破壞此假設時會死結而非亂序。
- 所有「結果與深度無關」的主張都以 §9 的深度掃描測試背書。

## 8. 選配：timer 中斷

KPN 下外部時間源會破壞確定性；若做，timer 以**已退休指令數**觸發
（Decode 計數，達到閾值送一個 token 進 mip.mtip），行為完全可重現。
預設不納入 v0.3 主線。

## 9. 測試計畫

沿用 rv32i 的三層式測試，全部以組譯器函式 + 手算/comptime 期望值撰寫：

1. **煙霧與 ISA 分組**：每個指令組一個 test（ALU/W 型、M、A、F、D、fcvt、CSR、trap 進出）。
2. **系統級**：harness 在資料記憶體映像中預建頁表（測試端以陣列運算產生 PTE），
   M 模式開機 → 建 satp → `mret` 進 S → 再進 U；MMIO 輸出排序陣列、走訪大陣列等實際工作。
   Sv39 測試：4KB/2MB/1GB 映射、權限違例、U 位、SUM/MXR、ASID + SFENCE.VMA 失效、
   未對齊、頁錯誤的 mcause/stval/sepc 檢查。
3. **err_\* 預期失敗示範**：WBD 不足、走訪通道破格、無效 PTE 導致的頁錯誤（改斷言訊息）。
4. **確定性性質測試**：同一程式以不同 const 泛型深度（`Core::<WBD>`、TLB 大小 1 vs 16）執行，
   斷言輸出 token 序列完全相同（規格 §3.10 性質 5 的直接驗證）。

### M1 實作筆記（2026-10-29）

- **120 位元上限的兩個繞道**：64 位元左移 `sll64` 分兩次移位、中間 wrap 回 u64；
  64×64 乘積 `mul_hi_lo` 用 32 位元學校乘法分塊（直接 `a * b` 最大近 2^128 會爆）。
  MULH/MULHSU 由無號積修正：`a_s·b_s = a_u·b_u − a_u·2^64·sb − b_u·2^64·sa (mod 2^128)`。
- **`wrap` 是取模不是符號擴展**：`.wrap::<u32>().wrap::<u64>()` 不會 sext；
  W 型指令的正確寫法是 `.wrap::<i32>().wrap::<u64>()`（先變負再擴展）。
- 模擬器 `/` `%` 恰為 trunc-toward-zero、餘數符號隨被除數，與 RISC-V 一致；
  但零除會直接報錯，spec 的除零特殊值（-1 / 被除數）須顯式 `if` 擋在前面。
- RV64 的 SLLI/SRLI/SRAI 移位量為 6 位元，classify 合法性檢查 `inst[31:26]` 而非 7 位元 funct7。
- 64 位元資料記憶體每字 8 位元組：32 位元視角的程式（以 4 位元組步距定址）
  需用 `dimage32()` 把 u32 陣列兩兩打包進 u64 字。

### M2 實作筆記（2026-10-29）

- **所有例外集中在 Decode**（非法/ecall/ebreak/未對齊/越界/CSR 違例；載存位址在 Decode
  就能算出並檢查）。trap = 「跳到 mtvec」的 token（C_TRAP）經 Execute → 既有 redirect
  通道送回 Fetch——與分支共用同一條通道，架構上不需要任何新通道。mret 同一機制跳回 mepc。
- **關鍵教訓（`--trace` 抓到）**：可能在 Decode 陷阱的指令（ZICSR、LOAD、STORE），
  Fetch 也必須停等 redirect；否則陷阱後 Fetch 已順序取入的下一條會洩漏進管線，
  被當成新指令執行，甚至觸發第二個陷阱**覆蓋 mepc/mtval**。沒陷阱時 Execute 送回 pc+4。
  行為模擬器不在乎效能，載存全序列化可接受。
- **結束模擬改為 `simexit()`**（存取自訂 CSR 0x7C0；Fetch 與 Decode 都認得，同步收尾）。
  ecall/ebreak 現在是真陷阱——這是 M2 對 rv32i 語意的最大語意變更，所有舊測試的
  結尾 `ecall()` 都要換成 `simexit()`。
- 看門狗改送標記 token `(0xFFFFFFFF, 0xFFFFFFFF)`：pc = 0xFFFFFFFF 必越界取 0，
  所以該組合不可能來自真實取指；Decode 收到後以 cause 2 收尾傾印。
- CSR 位址欄是 **u12**：0xF14 這類位址超出 i12，不能用 `enc_i`，需專用的 `enc_csr`。
- WPRI/WARL 以寫入遮罩實作：mstatus 只實作 MIE[3]/MPIE[7]/MPP[12:11]（遮罩 0x1888）、
  mepc 對齊遮罩 ~3；唯讀 CSR 寫入 → 非法指令（mtval = 指令本身，測試直接對照組譯器編碼）。
- mtvec 支援 direct/vectored（cause × 4）；mret：MIE = MPIE、MPIE = 1、pc = mepc
  （M2 僅 M 模式，MPP 恆回 3；S/U 進出在 M3）。

### M3 實作筆記（2026-10-30）

- **沒有獨立的 Translate task（偏離 §3）**：KPN 禁止非阻塞操作，Mem 無法在「管線埠」與
  「走訪埠」之間仲裁（§7 的「管線優先、否則服務 walk 埠」需要 `try_recv`）。改成翻譯在 Decode：
  TLB 是 Decode 的 `mem`，走訪讀取／A/D 回寫是 Decode 製造的 in-band token（`C_PTW_R`/`C_PTW_W`）
  經 Execute → Mem，**自動排在先前所有 store 之後**（程式先寫 PTE 再 sfence 的順序天然正確）。
  走訪前先排空記分板（inflight → 0），之後 wbq 上的下一個 token 必是走訪結果——零新通道。
- **取指翻譯**：Fetch 持一筆 ITLB（pc 頁 → 實體頁）。未命中時送 `F_XLATE` token，Decode
  翻譯後經 Execute 的 redirect 回「實體頁 | 1」，或在取指頁錯誤時直接進 trap、回 trap 目標
  （4 對齊 → bit 0 = 0，Fetch 以 bit 0 區分）。翻譯情境只會被停等型指令改變，所以 Fetch
  在分支/JALR 以外的 redirect 一律讓 ITLB 失效。`ifq` 改為 `(標籤, pc: u64, inst)`，
  看門狗不再用 `(0xFFFFFFFF, 0xFFFFFFFF)` 標記而是 `F_WDOG` 標籤；pc 全程 64 位元（高半部 VA）。
- **Harvard 實體位址**：取指的 PA 索引指令 ROM（`IWORDS` 擴為 256 字），載存與走訪的 PA 索引
  資料 RAM（`DWORDS` 擴為 2048 字 = 16 KB，放得下三層頁表）。同一個映射對取指與載存指向不同記憶體。
- **TLB**：`Core<WBD, TLBN>`，輪替取代；標籤含 V/G/層級/ASID/VPN，葉 PTE 每次存取都重新做權限檢查
  （所以 mstatus.SUM/MXR、特權模式改變立即生效，不需要 fence）。儲存命中 D = 0 的項目時當作未命中
  重走，由走訪設 D——TLB 永遠不必回寫 PTE。A/D 只在存取被允許時才設（特權規格的步驟順序）。
- **確定性**：`sv39_determinism_tlb_and_depth` 以 `Core<8,8>` 與 `Core<2,1>` 跑同一個 U 模式程式，
  斷言輸出、暫存器、退休數完全相同（stalls 除外，它本來就隨深度變）。注意此性質只對正確
  fence 的程式成立：不 fence 就改 PTE，看到舊或新映射取決於 TLB 大小（規格允許的不確定性）。
- **M2 的兩個規格偏差順手修正**：(1) mtvec/stvec 向量模式只影響**中斷**，同步例外一律跳 BASE
  （M2 讓 ecall 跳 BASE + 4×cause，測試因 nop 填充而沒抓到，已改測試）；(2) mret 後 MPP 設為最低
  支援模式 U（M2 時代只有 M，恆為 3）。mstatus 的 UXL/SXL 恆讀 2（`0xA00000000`）。
- 其他：`simexit` 在任何特權模式都可用（模擬器掛鉤，Fetch 本來就無條件停止）；WFI = nop
  （無中斷可等，「立即完成」使 TW 不觸發）；misa 唯讀；medeleg bit 11 恆 0；sie/sstatus 是
  mie/mstatus 的視窗、sip 讀 0；satp 寫入不支援的 MODE 整筆無效；傾印多一欄 D_PRIV（結束時的模式）。
- **仍未做**：取指越界/未對齊仍以非法指令（cause 2）報告，未改成 access fault / 在跳躍指令上報的
  misaligned；`err_*` 走訪通道破格示範（本設計沒有獨立走訪通道，失去意義）；中斷與計數器 CSR。

### M4 實作筆記（2026-10-30）

- 例外與翻譯沿用 M3 的 Decode 路徑：LR 是載入（未對齊 4、頁錯誤 13、存取錯誤 5），SC/AMO 是儲存
  （6/15/7，權限檢查要 W，硬體設 D）；atomic 一律要求自然對齊，碰 MMIO 是存取錯誤。
- 記憶體操作在 Mem 做（`kind = 4`，`val` 帶 funct5；Mem→Execute 通道的 kind 從 u2 擴為 u3）。
  rd = x0 的 AMO 照樣讀改寫，只是不送寫回 token（記分板本來就不為 x0 計數）。
- 保留集 = 一個位址，在 Mem：LR 設定，任何 SC（成功或失敗）清除。單 hart 下一般 store
  不清除保留——規格允許，且行為完全確定。aq/rl 在 in-order 單 hart 中沒有可觀察效果。
- `with_handler` / `record_handler` 從 tests_basic.fx 移到 rv64.fx 的 harness 區供各測試檔共用；misa 加上 A。

### M5 實作筆記（2026-10-30）

- **FPU 在 `rv64/fpu.fx`**（純 comb fn，rv64.sh 每條命令都載入它）。所有運算展開成「整數有效數 × 2^指數」
  的精確值，只在 `round_pack` 捨入一次。120 位元上限下的關鍵：加法/FMA 兩運算元先正規化到 116 位，
  指數差大時以 sticky jam 右移（差距 ≥ 10 位才會丟位元，相消最多 1 位，保護位元遠多於 2 位，
  jam 不改變捨入）；除法把被除數正規化到 116 位（商 ≥ 63 位）、開方先把指數調成偶數再整數開方，
  餘數非 0 都 jam 進最低位。round_pack 的編碼技巧：`((最低位指數 + m + bias − 1) << m) + 保留部分`，
  隱藏位元、非正規數進位成最小正規數、溢位到 ∞ 編碼都自然落進指數欄。
- **規格要點**：NaN 結果一律 canonical（RISC-V 不傳播 payload）；tininess 在捨入後判定；
  FMA 的 ∞×0 + qNaN 也舉 NV；fmin/fmax 一個 NaN 回另一個、−0 < +0；feq 只對 sNaN 舉 NV、
  flt/fle 對任何 NaN 舉 NV；fcvt 到整數超出範圍夾限並只舉 NV（NaN → 最大值），W/WU 結果符號擴展；
  單精度運算元未正確 NaN-boxing 視為 canonical NaN（fsgnj 也是），fmv.x.w 取原始低 32 位。
- **驗證**：`rv64/fpgen.py` 是獨立的參考實作——Python `Fraction` 精確值 + 「有理數比較與二分搜尋」
  決定捨入（與 fpu.fx 的位元演算法完全不同），本身先對照硬體浮點（雙精度 add/mul/div/sqrt、
  單精度 mul，3000 組零差異）。產生 `tests_fpu.fx`（19 組、約 16,000 向量，含五種捨入模式、
  特殊值、非正規數、近乎相消、溢位邊界、捨入後 tininess 的分界、FMA 的 NV 規則），
  直接驅動 `fp_op`/`fma_op`（指令層，含 rm 欄與 NaN-boxing）。重新產生：
  `python3 rv64/fpgen.py > rv64/tests_fpu.fx`（固定種子，輸出可 diff）。突變測試（RNE 改 ties-away、
  tininess 改捨入前、去掉遠端 jam、相消零的符號、−0 的 min、∞×0+qNaN）都會被抓到。
- **管線**：暫存器檔合併為 `rf[64]`（f 暫存器 = 32 + 編號），記分板與寫回 token `(u6, u64, fflags)`
  共用同一索引空間；fflags 隨寫回 token 累積，讀寫 fflags/fcsr 前先排空（程式順序）。
  寫 x0 的浮點指令（feq 等）仍送寫回 token 帶回旗標（Decode 收到時 x0 保持 0）。
  動態捨入（rm = 7）在 Decode 換成 frm 寫回 inst 的 rm 欄；保留的 rm（5/6，或 frm 無效時的 DYN）
  與 mstatus.FS = Off 都是非法指令——因為要到 Decode 才知道，浮點指令也讓 Fetch 停等 redirect。
  FS 重置為 Off（測試先 `csrs mstatus, 0x2000`），任何浮點指令保守地設 Dirty，SD 讀取時即時算出。
  FLW 由 Mem 做 NaN-boxing（f3 = 7）。傾印加上 f0..f31（`freg(r, n)`，DUMP_LEN 69）。misa 加上 F、D。
- **模擬器修正**（依 Fluxa 語意，非 rv64 專用）：右移量 ≥ 127 原本報「invalid shift amount」，
  現在是 floor 語意（0 或 −1）；`0 << n` 對任何 n 都是 0。FPU 的 sticky/捨入需要「移位量可能
  遠大於寬度」的右移。回歸測試：`examples/basics.fx` 的 `wide_shifts`。

### M6 實作筆記（2026-10-30）

- **中斷只在「等待點」接受**：Fetch 停等 redirect 的指令（`fetch_waits`：分支/跳躍、可能陷阱的指令、
  浮點）與取指翻譯請求。若在 Fetch 不停等的指令上接受中斷，trap 目標會滯留在 redirect 通道、
  Fetch 已順序取入的下一條會洩漏——與 M2 的教訓同一類。為此 **JAL 也改成停等**（Execute 回送目標），
  所以任何迴圈都含等待點、中斷必在有限步內被接受。CSR 寫入（例如設 SIE/MIE）讓 ITLB 失效，
  下一條的取指翻譯就是等待點，因此「打開中斷 → 下一條之前就進 handler」與硬體行為一致。
- **時間 = 已退休指令數**（§8）：`time`/`mtime` = retired，`cycle`/`instret` = retired + 寫入偏移
  （寫 mcycle/minstret 取代該指令本身的遞增）。mtimecmp 是自訂 M 模式 CSR 0x7C1（取代 CLINT 的
  MMIO；Mem 與 Decode 之間沒有反向通道），重置為全 1。mip.MTIP 即時算出、不可寫；SSIP/STIP/SEIP
  由 M 寫入（典型用法：M 的 timer handler 設 STIP 轉送給 S）；sip 只看得到/寫得到已委派位元。
  計數器權限：S/U 讀 cycle/time/instret 要 mcounteren 對應位元，U 還要 scounteren。
- 中斷優先序 MEI > MSI > MTI > SEI > SSI > STI；M 層在模式 < M 或 MIE 時接受，委派（mideleg）的
  在模式 < S 或（模式 = S 且 SIE）時接受、M 模式下永不接受。向量模式：BASE + 4 × 編號。
- **redirect 值的低兩位**：bit 0 = 取指翻譯回應、bit 1 = 翻譯情境可能改變（trap、xRET、sfence.vma、
  CSR 寫入）→ Fetch 只在 bit 1 時讓 ITLB 失效（M3 是除分支外一律失效）。
- **精確取指例外**：跳躍/成立分支的目標未對齊 → cause 0，報在跳躍指令上、tval = 目標
  （Decode 用運算元自己算目標與分支條件）；取指超出指令 ROM → Fetch 送 `F_IFAULT`，cause 1、tval = pc。
  M2 時代兩者都以「取到 0 → 非法指令」報告，對應測試已改。
- **寫回深度死結修正**（rv32i 繼承來的潛在問題）：Decode 原本只在資料相依或排空時才收寫回 token，
  連續超過 WBD + 3 個互不相依的寫回就會整條管線卡死（`interrupt_determinism` 以 WBD = 2 抓到：
  S handler 連續四個 csrr 之間夾著取指翻譯 token）。現在 Decode 的在途寫回數上限 = WBD，滿了先收一個，
  任何 WBD ≥ 1 都只影響停等次數。rv32i 保持原樣（`err_wb_depth.fx` 就是在示範那個死結）。
